# 自开发作业第一版实施方案

基准：`346e175`。用户已在能力审计后授权实施。独立工作树：`codex/self-development-20261026`；不推送、不安装、不改变正式账号数据。

## 取舍与评分

| 方案 | 评价 | 决定 |
| --- | --- | --- |
| worktree + 普通 shell | 5/10；有代码副本，仍可读账号、改主线 | 不作为隔离模式 |
| 独立 Git 数据库 + Docker worker | 9/10；源码、进程、网络与凭据分离；当前 Mac 已有运行器和 Node 镜像 | 本版采用 |
| 完整 macOS 虚拟机与独立更新器 | 9/10；可覆盖原生构建，但准备成本高 | 保留接口；本版不宣称 Linux 验收等于 Mac/iPhone 验收 |

## 本版交付

1. `test:full` 成为不安装的完整验证；正式覆盖安装只在显式 `release:verify` 入口执行。纯测试不改用户 Applications。
2. 开发作业持久化目标、仓库、固定基线、Agent、用户确定的验证命令、状态与证据。每个作业独立源码副本和 Git 数据库，不挂载主仓库、Docker socket、账号目录或宿主环境。
3. 容器默认断网、只读根文件系统、移除 capabilities、禁止提权、限制进程/内存/CPU。只挂载该次临时 Docker 卷；通过 Docker API 传入源码与独立 Git 副本，不使用宿主目录挂载。运行器不可用明确受阻，不降级普通 shell。
4. 实施复用现有 Agent 模型/人设和能力边界，仅提供作业文件操作与容器命令；不提供宿主 bash/MCP/委派。自动加载仓库规则，规则不能扩权。长命令有持久 ID、完整有界日志、退出码、超时/停止；重启核对旧容器并标记中断，绝不自动重放。
5. 控制端创建固定候选 commit。验证在候选副本执行，控制端保存命令、版本、退出码和日志哈希。只读审查 Agent 只能读取候选和证据，控制端要求实际读过证据及改动文件才能接受 approve；任何编辑/新基线使原验收失效。测试/CI/权限等敏感路径改动额外等待人工核对。
6. 桌面任务区提供创建、开始/继续、停止、日志、diff、验证和审查状态、导出候选包。通过后停在待合并；导出前再次核对目标基线与证据。本版不自动改主线引用、不推送、不覆盖安装；正式合并/更新器作为下一阶段，界面直说边界。
7. 将相同作业 ID、阶段、基线/候选、测试和审查摘要投影到现有 v1 任务检查点，iPhone/Android 均显示最近同步状态。手机不能通过同步写回可信验收或授权合并；本版手机远程控制不冒充已实现。

## 验收

- 两作业修改同文件互不覆盖、原仓库/WIP不变；缺少能力不能启动 worker。
- 真容器验证读宿主夹具、写宿主/正式目录、外网和宿主服务失败；子进程同样受限；环境不带合成秘密。
- 长任务日志/退出码/停止/进程树清理、持久记录和重启恢复；运行失败不出现假绿。
- 测试失败、证据修改、候选变动、主线变化、审查拒绝均不能导出“可合并”包；敏感路径需要额外人工确认。
- 自动化夹具模型完整走实施 → 测试 → 只读审查 → 待合并，并通过真实 HTTP 和桌面浏览器操作验证。
- 现有任务/同步兼容回归、桌面/UI语言检查、手机协议及原生编译按影响范围执行；真实模型、真机安装另列，不用夹具冒充。

## 使用与边界

1. 在可信环境先运行 `npm run build:development-image`，生成 `melo-development:local`。构建上下文只包括锁文件、构建声明和原生模块源码，不发送仓库、账号或运行数据。依赖下载只发生在这一显式准备步骤；作业执行默认断网，不自动降级宿主 shell。
2. 桌面「工具与任务 → 隔离开发」选择已提交仓库、实施/审查 Agent、目标与必需验证命令。只复制指定提交；未提交 WIP 不包含在候选里，也不修改它。当前验证命令使用 JSON 参数数组，例如 `[["node","--test","src/development/service.test.js"]]`；Linux 无法运行 Swift/Xcode 验收，请单独完成原生平台验证。
3. 启动后可查看版本、diff、每条命令日志和审查结果。测试/权限/执行入口等敏感修改必须人工核对此候选后再导出；导出包含可应用的完整补丁及版本/回执哈希，但不执行合并。
4. 手机同步同一个作业 ID、阶段、候选和验收摘要，不能修改可信回执或发起授权。真实 Mac/iPhone 安装、健康检查、自动回滚，以及受控合并/更新器仍是后续阶段。
5. 本版以固定命令的真实退出码、测试前后源码树一致和独立审查作为接受条件；并未证明测试覆盖充分，也未实现跨所有测试框架的“跳过数/断言数”机器证明。CPU/内存/进程与日志有上限；输出回传限制 512 MiB，Docker 临时卷写入期间尚无统一磁盘硬配额。

## 可重跑证据

- `npm run test:development`：作业、能力、路径、拒绝条件、恢复、同步及 UI 回归；追加 `scripts/release-policy.test.js scripts/native-translations.test.js` 以及 UI 翻译覆盖、工具注册规范为本轮 35 项专项范围。
- `npm run test:development:container -- --prepared`：实际 Docker、无宿主凭据/文件/网络、Git 元数据隔离、Linux 原生依赖、停止及清理。
- `npm run test:development:container -- --long`：额外进行超过十分钟的真实命令。
- `npm run test:development:journey`：临时仓库/数据、确定性模型、真实桌面浏览器/HTTP/执行器/容器；截图、服务日志与验收 JSON 路径由输出记录。
- `npm run test:full` 只验证；`npm run release:verify` 才含安装，并且安装位于所有纯验证之后。

- 证据归档：`.tmp/self-development-implementation-20261026/`。在真实容器里对 Melo 自身提交 `0f6cbff` 的开发作业模块运行 19 项回归，全过、无跳过，候选源码树保持相同；这是特定模块的 Linux 验收，不是全产品 Linux/原生验收。
