# 图片提示词与结果核对优化 · 2026-10-10

用户要求在已有 Image 2 通道上优化图片处理。此次调整集中在需求保真、编辑边界和结果检查，不替换用户选择的模型，不额外增加一次提示词规划请求。

## 已接入的流程

- Codex 文生图、参考图生成、两阶段改图，以及 Images 兼容 API 共用视觉要求规则；普通聊天的 Codex 内联生图也接入相同的要求优先级。主体、用途、构图、风格、指定文字和限制由已有生成调用处理，原始用户要求保持完整。
- 用户明确要求的修改优先于默认保留项及视觉分析。编辑只改指定属性；基于参考图创作新图不会无条件锁死第一张参考图的构图。主体、风格、构图和一般参考分开标注。
- 移除 Codex 的 300 / 4,000 字符静默截断。Melo 本地要求上限为 24,000 字符，超限在生成前报错；这不是对所有兼容供应商上限的承诺。视觉分析摘要限长时明确标为片段，原图仍随请求发送。
- MiniMax 保留原有 1,500 字符通道限制，但超限不再截断后继续生成。其提示词及本地 sd.cpp 仍遵循各自原流程，不把长英文指令模板强加给这些引擎。MiniMax 限制依据：[官方工具说明](https://github.com/MiniMax-AI/skills/blob/main/skills/frontend-dev/scripts/minimax_image.py?plain=1)。
- 新图和编辑均可在“图片选项 → 核对生成结果”中启用检查；每张增加一次视觉请求。默认不打开，不自动补图、换服务或重试。检查结果随图片回到聊天，也写入真实执行事件。
- 核对采用结构化结果；无法解析、缺少观察或结论自相矛盾时显示“需人工核对”，不会当成通过。图片先交付，检查失败仍保留图片。

编辑保留、参考图角色及精确文字约束参考 [OpenAI 官方图片提示指南](https://developers.openai.com/api/docs/guides/image-prompting)。生成质量还需按具体任务判断，提示规则和视觉核对均不构成像素级保真保证。
