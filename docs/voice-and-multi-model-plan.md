# Melo 语音输入、多模型协作与 GPT-Live

核对日期：2026-10-08。语音输入已实施；多模型预算与 GPT-Live 为下一阶段设计，不能当作已接通的功能。

## 1. 本轮先交付语音输入

Mac、iPhone 使用 Apple Speech，网页使用可用的 Web Speech Recognition。点击麦克风开始、再次点击停止，转写追加到当前草稿，由用户修改并发送；不替换已有附件，也不直接发出聊天请求。支持中文、英语与系统语言，显示实时转写、取消、权限与网络错误。

每次录音绑定独立会话，旧权限回调、重复最终结果、切换对话后的结果都不能进入另一份草稿。停止后等待最终尾字；服务未确认时保留当前文字并提示核对。最长 60 秒；隐藏网页或离开手机对话时取消录音。系统识别可能联网，不能宣称所有设备都离线识别。不支持识别的浏览器显示系统键盘听写或桌面版入口说明。

原生状态控制器由 Mac 和 iPhone 共用：`ios/Melo/VoiceInput.swift`；Apple 适配器是 `SystemSpeechInput.swift`，浏览器/原生桥接控制器是 `desktop-ui/voiceInput.js`。此功能只产生用户确认后的文本，不需要新增 LLM Key，也不消耗 Melo 发给模型的请求额度。

## 2. 多模型协作先解决什么

用户可以将已有 API 或可用 OAuth 连接分配给任务角色。任务规划、记忆、权限、工具调用、取消、恢复和最终验收全部保留在 Melo。不开多个供应商代理运行时，也不以切换全局模型的方式模拟并行。

已有基础：

- `src/services/settings/llmConnections.js` 保存独立 `llmProfiles`、修订号和实际请求测试。
- `src/agents/team.js` 有调查、执行、复核三个角色；调查和复核为受限只读，最多两个并行；包含执行角色时串行。
- 目前所有角色共用传入的 `config`，尚未按角色绑定独立模型连接。
- `src/runtime/usage.js` 已读取供应商用量回执，缺失用量和缺失价格保持未知；尚无跨角色的任务总预算预留。
- `subAgent.js` 有深度与轮数限制，但轮数不等于 token 上限。Anthropic 当前固定 `max_tokens: 8192`，其他协议也尚未贯通统一任务输出上限。
- 手机已有独立模型对话和桌面任务接力；不能把桌面工具协作能力标成手机本地已拥有。

## 3. 默认方式：按任务分工，遇到问题再升级

| 策略 | 适用任务 | 执行方式 | 主要代价 |
| --- | --- | --- | --- |
| 单模型基线 | 普通问答、短文本改写 | 一个已验证可用模型完成 | 最少调度开销 |
| 分级执行（推荐默认） | 大多数日常任务 | 合适模型先执行；验收失败、证据不足时按预算升级一次 | 避免每题固定调用所有模型 |
| 分工协作 | 调查后写作、实现后复核 | 调查提供证据 → 执行产出 → 独立模型复核 | 更长时间，适合确需检查的任务 |
| 有限并行 | 可以独立调查的子问题 | 最多两个只读分支并行，合并证据后统一输出 | 可能降低墙钟时间，但增加总 token |

普通计算、简单问答不启动全体角色。复核者必须在产物可用后读取产物，不能在执行前启动却声称“已复核”。副作用工具维持单一执行所有者，调查和复核不扩大权限。已确认发生的写入、发送和外部操作不得因换模型再执行一次。

初期由用户手动指定“主执行 / 调查 / 复核 / 升级”连接，缺少模型时合并角色或回到单模型，并说明实际参与者。自动分配仅在积累可比较的真实记录后启用。用户随时可选择仅使用当前模型。

## 4. 任务预算：API 与订阅分开

### API

设置任务总 token 预算、单次最大输出、最大请求数、超时、并行上限；可选按用户核对的单价设置费用预算。所有主模型、规划、工具循环、复核、重试、上下文压缩和升级请求共同计入总账，不能只统计最后回答。

请求前预留“预计输入 + 输出上限”，并行分支必须原子占用剩余预算；请求后使用真实 usage 结算并释放多余预留。缓存 token 依供应商字段规范化，不能重复计数；计费单价与单纯 token 数分别展示。价格索引使用 `profileId + providerId + modelId + pricingVersion`，避免不同平台同名模型套错价格。

输入估算不是供应商账单；只有接口支持明确输出上限时才可承诺限制该次输出。不能保证准确预估所有供应商的输入、隐藏推理或断流费用。usage 缺失、连接中断或结果不确定时保留未知预留，暂停新增分支或要求用户继续；不能记成零，也不能自动开始另一轮付费请求。

达到预算时保留已有结果，显示“已用尽本任务预算，尚未完成哪些步骤”。不截断正在发生的不可逆外部操作来假装零超支；取消请求也不能承诺服务端已停止计费。

### 订阅 / OAuth

订阅额度通常是滚动窗口内共享的动态限额，不能把“每任务 10% 订阅额度”实现成精确硬上限，也不能把一次请求换算成固定额度。OpenAI 官方说明额度消耗随模型和任务而变，购买积分的计价表不决定订阅内含使用量。[官方订阅说明](https://learn.chatgpt.com/docs/pricing)

可执行的设置是 **每任务最多请求数、最长执行时间、最多升级次数、并行上限与可支持的推理强度**。例如“最多 8 次模型请求，120 秒，最多升级 1 次”是产品预设示例，不代表供应商额度。界面显示实际请求次数和耗时；只有平台公开且允许 Melo 调用的配额接口返回可信数据时，才显示其剩余额度和重置时间，并标明更新时间。没有数据时显示“平台未提供”，不从网页爬取或虚构比例。

授权形式与计费形式分开：OpenRouter 浏览器授权得到的是其 API 访问能力，不能因采用 OAuth 就标为包月无限订阅。不同连接可分别设置限制，任务还要有统一总次数/时间上限。

## 5. 建议实现结构

新增的结构是设计草案，尚未写入运行配置：

```json
{
  "mode": "escalate",
  "roles": {
    "primary": {"profileId": "chosen-profile", "model": "chosen-model"},
    "reviewer": {"profileId": "another-profile", "model": "another-model"}
  },
  "budget": {
    "apiTotalTokens": 40000,
    "maxOutputTokensPerRequest": 4000,
    "maxRequests": 8,
    "maxDurationMs": 120000,
    "maxEscalations": 1,
    "maxParallelReadBranches": 2
  }
}
```

1. `resolveTaskModelBindings` 在任务建立时绑定 home、连接修订、模型、协议和能力；凭证只留后端。不得调用 `activateLlmProfile()` 临时改全局模型。
2. `TaskBudgetLedger` 持久化预留/结算/未知用量，按 taskId/requestId/attemptId 幂等更新。重启不能重置预算；同一家庭目录下并行任务也要遵守账户级并发限制。
3. `modelRequestPolicy` 为各协议映射真实支持的输出上限、工具/图像能力和流式 usage。未支持的参数不随意发送；用户要求严格控制而平台无法支持时，阻止启动并说明缺口。
4. 扩展现有 `runAgentTeam` 为带依赖的任务图，角色直接使用绑定配置。继续复用现有 `runSubAgent`、权限网关、工具记录和任务验收，不再造一个工具循环。
5. 每个模型请求记录连接、请求模型、返回模型、开始/结束时间、真实 usage、取消/失败以及结果来源。任务空间展示实际发生的调用和交接；不将装饰脉冲当作内部思维。
6. 结果依旧写入现有聊天、来源、候选成果和执行场景，完成回执写入现有跨端协议；手机发起桌面协作须明确显示执行设备及离线状态。

设置页建议保留三个入口：单模型、自动分级、指定协作。展开后选择角色模型及预算；运行时可见“2 个模型 / 3 次请求 / 已知用量 / 未知用量”，在超预算前保留可继续的检查点。

## 6. 怎样确定“哪个效率最高”

现在不能给出可信的厂商排名：尚未以同一任务集、同一账户条件实测所有已支持的平台。“测试实际请求”的 `2+2` 只证明连通，不能证明工具执行、研究质量或协作效率。

建立一组固定任务，覆盖短问答、复杂约束、带来源检索、资料归纳、受限文件修改。相同输入和验收条件下比较上表策略，每项至少重复三次，并保留模型、配置、提示词和测试集版本。先跑无需真实凭证的协议与预算测试，再仅对用户选中的可用连接跑受预算限制的实测。

评价顺序：验收成功率、严重错误与权限违规 → 每成功任务成本 → 完成时间中位数/P95 → token 和请求次数。订阅任务将应用请求数、耗时和实际可得配额分开统计；不同单位不强行折算。样本不足标为“证据不足”。按任务类型给出建议，不宣布一个模型在所有任务上最快最省。

建议实施顺序：绑定与预算账本 → 单模型预算闭环 → 分级升级 → 独立复核 → 只读并行 → 小规模实测与自适应选择。单模型基线未过验收时，不用增加模型数量掩盖问题。

## 7. GPT-Live 可以实现，且能保留 Melo 的 harness

官方现在提供 `gpt-live-1`。它支持边听边说，并提供 **client delegation**，可把任务交给应用自己的模型、工具或代理系统。Melo 应选择这一模式，语音前端与任务执行分离：GPT-Live 负责低延迟对话；Melo 负责检索、计算、执行、权限与多模型预算。[GPT-Live 概览](https://developers.openai.com/api/docs/guides/live)、[客户端委派](https://developers.openai.com/api/docs/guides/live-delegation)

建议链路：麦克风 → WebRTC GPT-Live 会话 → 转写及委派事件 → Melo 任务入口 → 现有执行事件/结果 → GPT-Live 播报，并同时落在可阅读的聊天区。

服务端以获准使用 GPT-Live 的 OpenAI 项目 API Key 创建会话，配置 `model: "gpt-live-1"` 与 `delegation: {type: "client"}`。WebRTC 信令是 `/v1/live/sessions`，不要混用 Realtime 的 `/v1/realtime/calls`。密钥保留在可信服务端；手机不能连接 Mac 时，需要独立可信的会话服务，不能将桌面本地端口当成手机云服务。[WebRTC 官方指南](https://developers.openai.com/api/docs/guides/voice-webrtc?voice-api=realtime)

`session.delegation.created` 不直接携带完整任务正文，需结合带时间戳的转写事件、委派偏移和 Melo 对话上下文解析意图；不能把尚未完成的片段误当成用户的执行指令。将可验证进度与结果送入官方支持的 commentary/thinking 通道；涉及权限的任务仍在 Melo 确认后执行，语音中的“我会处理”不构成成功回执。[委派事件说明](https://developers.openai.com/api/docs/guides/live-delegation)

实时插话先停止当前播报；是否取消后台任务由 Melo 判断用户明确意图。断线时停止麦克风/扬声器、关闭会话并保留任务记录。真实任务可继续时展示状态；重连不能自动重复外部操作。隐藏界面、结束通话或超时都必须释放 WebRTC track、数据通道和服务会话。

GPT-Live 的语音会话按时长计费，委派模型与工具另计，预算应增加“本次通话最长分钟数/费用”并独立结算。[计费与生命周期](https://developers.openai.com/api/docs/guides/live)

**授权限制：** 现有 Melo 的 ChatGPT/Codex OAuth 文本推理连接，不能据此声称已经拥有 GPT-Live API 权限。官方 GPT-Live 接入文档要求项目 API Key 和模型访问权限。先增加独立的实时语音连接与实际会话测试，不改动现有文本模型连接，也不承诺复用 ChatGPT 消费订阅。

第一阶段仅接听说、字幕、插话、结束和文本聊天交接；第二阶段接入 Melo 任务委派、权限暂停、预算与恢复；第三阶段再将多模型协作接到同一任务入口。未测试真实 GPT-Live 账号和音频会话前，不展示“已接通”。

## 8. 本轮验证边界

- 305 项 UI 基线通过；完成后 313 项 UI 测试通过，含浏览器/原生桥接的会话、取消、尾字、去重和错误保留。
- 10 组 Swift 测试及场景桥接通过；新增共享语音状态机测试覆盖授权期间取消、旧回调、完成、超时与草稿追加。Mac 与 iOS 模拟器均编译成功。
- 隔离网页以明确的模拟识别事件走通“已有草稿 → 实时转写 → 停止 → 文字追加”，无自动聊天请求、无前端错误。这验证界面与事件链路，不是麦克风识别准确率测试。
- 完整桌面门禁：40 GREEN / 2 YELLOW / 0 RED。两项自动原生启动测试显式跳过，实际正式桌面包已安装、签名验证并通过原生窗口检查，显示新的麦克风及语言入口，仍有原来的 9 段对话和 6 个角色。未把启动当作麦克风录音验收。
- 另修复了应用包资源签名，并把诊断写盘移离主线程：重启采样确认同步日志写入曾阻塞窗口启动。
- 本轮未采集用户麦克风，也未验收真机 iPhone 录音；不同设备的系统权限、语言支持、联网识别和噪声环境仍需设备端实测。
- 多模型协作预算和 GPT-Live 尚处设计阶段；未运行付费多模型竞赛或创建真实 GPT-Live 会话。
