用户在协作扫描后要求“全部按顺序改”。分支 `claude/agent-team-20261016`，基于 `105a0f4`。只改电脑端；手机对话不经过电脑执行器，本轮不加手机团队功能。

## 设计决定

- **一个委派开关**：Agent 设置里只保留能力中的“委派”。保存时同时写入协作里的 `canDelegate`（同步协议仍要求这个字段，旧手机照常读写）。执行时仍要求两者都开，所以旧数据里两者不一致时只会更严，不会意外放宽。
- **团队与委派同一规则**：团队的发起者是当前对话的 Agent；它必须开启委派，且每个成员都在它的“委派对象”里。过去团队只看能力开关、不看名单。
- **成员按名字勾选，按勾选顺序执行**：协作面板只列出当前 Agent 的委派对象；没开委派或没有对象时直接说明去哪里设置。存储的委派对象按 ID 排序，不代表先后，所以顺序取勾选顺序并实时显示；没有保存的团队时默认不勾选。
- **主 Agent 汇总**：成员结束后，由发起的 Agent 用一次模型调用写出给用户看的结论；交接记录留在执行明细。调用失败、取消或超出预算时，改用按交接记录生成的固定格式摘要，不会显示原始 JSON。
- **编排**：并行模板改为“前面的成员并行调研，最后一位复核全部结果”；复核循环第二轮起，实施成员同时拿到自己上一轮交接和复核意见；团队有总时间（默认 15 分钟）和总 token（默认 30 万）上限：时间用完会取消正在运行的成员；token 用完不再启动新成员。只计入服务报告了用量的请求。
- **项目**：项目可设默认 Agent（项目内新对话使用）和默认团队（模板 + 成员），在项目详情页管理。这两个字段只存在电脑，不进入同步协议（项目同步格式对旧客户端严格校验）。

## 手机端团队（2026-10-16 续，用户要求“手机端团队做完”）

手机对话由手机直接调模型，不经过电脑执行器，所以手机团队在手机上运行，按电脑的同一套规则：

- **谁能组队**：读同步过来的 Agent 协作设置（委派开关 + 委派对象），与电脑一致；手机上不另设一套。手机本地 Agent 没有协作设置时不能发起，面板说明需要在电脑上开启。
- **成员能做什么**：每位成员在手机上调用一次模型（文字 + 交接记录），不使用手机数据工具、不生成图片；联网搜索要求发起者和该成员在“这台手机上”都开了联网。
- **编排**：与电脑相同的三种方式（接力、并行调研后复核、实施/复核循环，最多 2 轮），按勾选顺序；发起的 Agent 写最终汇总，失败时用固定格式摘要；团队总时间上限 15 分钟。手机回复不带用量数据，所以没有 token 总上限（逐项列为平台差异）。
- **入口**：对话控制栏新增“团队”，在弹出页勾选成员和方式，作用于下一条消息，发送后自动取消，避免误用产生多次调用。

### 手机端验证与边界

- 共享契约新增交接解析（7）、计划校验（8）、执行顺序（6）三组，JS 与 Swift 读同一份数据；改坏 Swift 的代码块剥离或循环交接，契约测试都会失败。`AgentTeamTests` 用计数证明：发起者规则、时间预算会停掉运行中的成员且不再启动下一位、取消后不调用任何成员、失败成员如实报告、并行最多 2 个且复核最后执行。
- 模拟器（Debug，`-melo-verify-team`）走真实 `ChatStore.send`：未勾选成员被拒且无请求、无消息；按勾选顺序“复核员 → 调研员”执行，第二位收到交接；回复为发起者汇总并归属发起者；执行记录有逐成员阶段；团队发送后自动取消，下一条消息恢复普通回复。
- 模拟器实看：控制栏“团队”放在 Agent 旁边（原先排在末尾、默认看不到）；弹出页与“项目与资料”同风格，勾选显示序号和执行顺序，选定后控制栏变为“团队 · N 人”。修正一处：同一视图上两个 sheet 只有一个能弹出，团队页改挂在自己的按钮上。
- 未验证：真实账号下的成员与汇总调用；实体 iPhone；通过界面点发送（模拟器中文输入法候选栏挡住发送键，发送路径已由上面的真实 `ChatStore` 验证覆盖）。含发起者名字的两句说明未进五语目录（插值文案），其余新文案已加。
