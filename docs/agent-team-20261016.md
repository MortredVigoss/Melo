## 设计决定

- **一个委派开关**：Agent 设置里只保留能力中的“委派”。保存时同时写入协作里的 `canDelegate`（同步协议仍要求这个字段，旧手机照常读写）。执行时仍要求两者都开，所以旧数据里两者不一致时只会更严，不会意外放宽。
- **团队与委派同一规则**：团队的发起者是当前对话的 Agent；它必须开启委派，且每个成员都在它的“委派对象”里。过去团队只看能力开关、不看名单。
- **成员按名字勾选**：对话和任务里的协作面板只列出当前 Agent 的委派对象；没开委派或没有对象时直接说明去哪里设置。
- **主 Agent 汇总**：成员结束后，由发起的 Agent 用一次模型调用写出给用户看的结论；交接记录留在执行明细。调用失败、取消或超出预算时，改用按交接记录生成的固定格式摘要，不会显示原始 JSON。
- **编排**：并行模板改为“前面的成员并行调研，最后一位复核全部结果”；复核循环第二轮起，实施成员同时拿到自己上一轮交接和复核意见；团队有总时间和总 token 上限，超出后不再启动新成员并取消仍在运行的成员。
- **项目**：项目可设默认 Agent（项目内新对话使用）和默认团队（模板 + 成员），在项目详情页管理。这两个字段只存在电脑，不进入同步协议（项目同步格式对旧客户端严格校验）。
