## 核实后的通道差异

- 真机 0.5.16 (21) 的失败请求已绑定原图，模式 edit、图片型号 gpt-image-2、语言模型 gpt-6-astra；未取得工具或成品事件。此次不是意图识别漏掉。
- 旧版手机使用 Sign in with ChatGPT 动态注册，resource 为 api.openai.com/v1。[官方预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) 明确不支持 hosted image generation；普通图片输入可用。此次手机改用独立 Codex 授权，不再从这条通道发请求。
- 桌面 Codex OAuth 使用 chatgpt.com/backend-api/codex/responses，是另一套登录令牌与授权。2026-10-10 的真实生成和编辑证据返回 gpt-image-2-codex，不是 gpt-image-2.1。不能将手机通道限制泛化成全部 OAuth 限制，也不能将手机现有令牌直接挪到 Codex URL。
- 本轮再次通过桌面生产引擎、既有 OAuth 及旧测试图核验；不使用用户上传的室内照片。随后按用户要求补齐手机独立 Codex 登录、刷新及调用链；原 API 图片连接仍为可选通道。

## 手机统一 Codex OAuth 方案（用户要求已实施）

用户最初要求补图片登录，随后明确“直接手机上也改成 codex 登录”。因此最终将手机的订阅聊天、看图、搜索和生图统一接入 Codex；保留现有对话的连接标识与 API Key 选项。

1. 独立的手机 Codex 账号：按官方 `openai/codex` 的 device_code_auth 实现申请验证码、限时轮询、PKCE 换令牌；身份签名校验后写入本机 Keychain，刷新串行化，取消/退出阻止迟到结果写回。
2. 系统设置与图片设置均提供登录入口、复制验证码、官方网页入口和授权状态；原 SIWC 凭证保持存储但不再使用，新凭证写入独立 Keychain 项；必须重新授权。登录不自动生成测试图；实际修图成功才标记图片能力已验证。
3. 聊天与图片任务通过 Codex 直接调用 `chatgpt.com/backend-api/codex/responses`，携带本机独立令牌与账号 ID。复用 Melo 的原图、提示词、结果落盘与执行事件；不运行 Codex harness，不静默换 API 计费。
4. 离线验证设备码等待/取消/超时、PKCE、身份、刷新和图片 SSE；编译与模拟器验收后提供用户自行登录验证。真实手机账号额度与服务端权限只能在用户授权后确认。

依据：[Codex 授权说明](https://developers.openai.com/codex/auth/)、[官方设备码实现](https://github.com/openai/codex/blob/main/codex-rs/login/src/device_code_auth.rs)、[官方令牌刷新](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/manager.rs)。设备码功能可能需要用户先在 ChatGPT 安全设置 / 工作区权限开启。
