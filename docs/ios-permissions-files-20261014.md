# 手机版权限与文件访问专项

用户确认本轮完善 Melo 内的权限管理和文件访问。此次不是全量三线程对齐，也没有授权立即覆盖手机；保留共享工作树及原神经界面。

## 计划与验收

| 顺序 | 现状 / 用户要求 | 实现 | 验收 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 设置只有系统跳转，不显示真实权限 | 集中显示麦克风、语音识别、保存照片、通知的状态；未申请时由按钮请求，拒绝后引导系统设置，返回自动刷新 | 原生读取状态、实际点击麦克风申请及拒绝，页面未自动弹窗 | 已实现；模拟器通过 |
| 2 | 文件入口零散，不支持持续访问目录 | 用户选择文件或文件夹；文件夹书签仅本机持久化，可撤销、失效后重新授权 | 记录重新载入、路径越界、软链接、无效书签、保存失败；原生浏览目录 | 已实现；本地与模拟器通过 |
| 3 | 不能方便预览和使用文件 | 应用内系统预览；TXT/Markdown/PDF 提取可选入知识资料，明确确认保存及模型使用范围 | 超限、非 UTF-8、扫描 PDF；UI 取消后零资料，明确保存后仅新增一份并显示绿色已保存 | 已实现；原生 PDF 预览和导入通过 |
| 4 | 权限与业务开关容易混淆 | 相册选图无需整库授权；朗读无需麦克风；通知权限与通知偏好独立；不增加无对应功能的权限 | 20 组 Swift 回归、共享 JS/渲染校验、Debug 模拟器及 iPhoneOS Release 构建 | 通过 |

权限申请只由明确操作触发，不在进入页面时索要；文件授权不会自动上传、同步文件路径/书签或启动模型请求。不提供整机扫描，不承诺无限后台运行。

新增入口沿用 Melo 面板、状态颜色与透明布局；目录授权撤销只移除访问记录，已明确导入的知识资料保留。生成内容和完整 PDF/Office 编辑不属于本轮。

源码基线与证据：`.tmp/ios-permissions-20261014/`。构建、模拟器与真机结果分开记录。

## 结果与边界

- 入口：系统设置 → 权限与文件；知识 → 导入文件。权限状态分为尚未申请、已允许、未允许、系统限制、静默通知；返回前台自动刷新。
- 目录记录单独存放在本机 Application Support/MeloLocalAccess，完全文件保护并排除系统备份，不进入工作区同步、资料导出。撤销记录后需要重新选择授权；原文件与明确保存的知识资料不删除。
- 一次浏览只读取当前目录，最多 500 项；预览有界读取最多 20 MB，临时副本在关闭预览后清理，拒绝符号链接与越界组件。文件读取经系统文件协调器处理，并在后台队列执行。
- TXT/Markdown 需 UTF-8，PDF 需文字层、最多 200 页；知识资料上限 12,000 字，超限明确拒绝，未静默截断。Office 仅在系统支持时预览，不提取正文。
- 原生 fixture 首次失败是复用 PDF 测试渲染器未生成第二份文件；改为独立 PDF 数据写入并验证页数，最终 fixture 全通过。PDF 预览、取消、保存与实际持久化经过 Device Hub 点击验收。
- 新增 1 组有真实磁盘读写的 Swift 回归，已接入 `npm run test:ios`；最终 20 组 Swift 与共享渲染检查通过。未运行会安装/重启桌面的完整 npm test。
- 此次没有更改实体手机权限、没有签名打包或覆盖安装。iCloud/第三方文件服务的真实文档选择、授权到期恢复、实体设备权限允许流程仍需真机验收；模拟器书签与状态结果不代替这些检查。

苹果 API 依据：[目录授权与书签](https://developer.apple.com/documentation/uikit/providing-access-to-directories)、[照片选择器的按项访问](https://developer.apple.com/documentation/swiftui/view/photospicker(ispresented:selection:matching:preferreditemencoding:photolibrary:))。
