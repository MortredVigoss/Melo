## 根因

1. `src/runtime/paths.js` 在没有 `MELO_HOME` 时把数据目录解析到 `<项目>/.tmp/melo-home-user`，测试进程也一样。
2. 三份走真实执行图的测试在模块顶层 `await test(...)`，同时用根级 `after()` 恢复 `MELO_HOME`。Node 22 在第一个顶层用例结束时就执行根级 `after()`，后面的用例运行在恢复后的环境里。三份文件是 `turnEffectsRepeat.test.js`（我 11-05 写的）、`taskEvaluationGraph.test.js`（11-05）、`deferredTools.graph.test.js`（我今天写的，照抄了旧文件的写法）。
3. 门禁（`verify-daily.js`、`run-unit-tests.js`）给子进程设了隔离目录，所以门禁里一直是安全的；直接运行才会出事。我今天为了快，绕开门禁直接跑了目录，这是我的错误。
4. 11-07 的修复只改了当时出事的那份文件，没有防住同类写法，也没有在路径解析上兜底。

## 已做的防护（代码）

- `src/runtime/paths.js`：测试进程（Node 测试运行器的子进程，或入口脚本本身是测试文件）没有 `MELO_HOME`、或者 `MELO_HOME` 指向用户数据目录时，一律解析到本进程的一次性临时目录，来源标记为 `test-isolated`。只有显式设置 `MELO_ALLOW_USER_HOME_IN_TESTS=1` 才例外，仓库里没有任何地方设置它。正式应用和命令行不受影响。
- `src/runtime/testIsolation.test.js`：三项测试。一是解析结果；二是真实复现事故路径（子进程删掉 `MELO_HOME` 后调用 `saveState`），断言状态写进了临时目录、用户目录的状态文件修改时间不变；三是扫描全部测试文件，拒绝"根级 `after()` + 顶层 `await test()` + 改 `MELO_HOME`"的写法。
- 三份测试改成"一个父用例包住全部子用例，清理放在 `t.after`"，每个子用例入口断言 `MELO_HOME` 仍是夹具目录。
