## 执行链与边界

桌面：聊天 UI → `chatRoutes` → `sendChatMessage` → `chatExecutionRunner` → `prepareNode` → `invokeModelNode` → `internalMembers`/`subAgent` → `executor` → `goal` → `finalizeNode` → SSE/消息原子保存。状态包括请求作用域、预算/权限/副作用账本、临时执行记录、上下文和消息存储。

iPhone：`ChatStore.send` → `ChatGPTAccount`/`Network` → `AgentLoop` → 模型适配/成员和工具调度 → `goal` → finalize → `ChatStore`/`ContentView`。`LoopTrace`、`ExecutionRecord`、本机恢复 checkpoint 是观察与恢复投影，不能作为执行授权。模型断流、限额、用户取消、后台暂停分别传回原错误分支，正式消息仅在核验与保存完成后提交。

共享核心 `goal`/`internalRouting`/执行契约的 Android 消费方一并核对生成资源与回归。v1 线协议不增加必填字段。网络传输和 WebView 是外部边界，工具权限、执行回执、预算均由原入口判断；只读并行也不绕过它们。

## 实施范围与新增边界

- 手机 API key 的 Chat Completions / Anthropic SSE 与 Codex 正文增量接入 `ChatStore.replyDrafts`，仅在内存暂存，草稿明确标识未完成核验；退出/取消/异常清理，正式消息仍经原提交路径。逐请求独立 ID、首网络事件/首正文、模型用时以及活跃/暂停时间进入原执行面板。
- `goal.js` 将不确定断言核验合入现有完成审核；只复用已验证的同一候选/修订/原文引用，其他情况仍调用原兜底检查。未变化的失败候选可复用同一审核的拒绝结果，且仍消耗原纠偏额度、检查全部证据约束；改写、补充、能力、资料或上下文变化必须再审。桌面审核上下文使用原聊天与真实补充，工具证据单独传递，宿主的纠偏提示不再被伪装成新用户要求。
- `AgentLoop` 支持同批最多两个独立只读成员，每个使用独立 transport/模型观察、子预算、同源检查循环、唯一工具 ID；主预算统一预约，写入和依赖派发串行。子边界把已完成读取与回执汇总到主 checkpoint；中断后从原证据重规划，不能恢复旧权限。`APIChatTransport.forkForMember` / `CodexResponsesTransport.forkForMember` 是实际入口，不新增或迁移凭证及设置，不创建新账号。
- 普通 `open_url` 同批两路执行，结果按请求顺序回传、执行面板按实际完成时间记录。`PhonePageHTTP` 先匿名读取静态正文，2 秒内不可用/受限/动态壳回退 WebKit，两条路径共用原 20 秒截止。重定向仍按公开 URL 规则，禁用 HTTP cookie/cache；静态 HTML 进入惰性 template，脚本与资源不执行。WebKit 语义正文稳定可提前返回并明确标记页面未完全加载；截图继续完整加载。
- 分页缓存仅限同一轮、完整成功的源，30 秒/8 个源；记录 URL、SHA256 内容版本和取得时间，首分页刷新前清除旧快照，刷新失败不能把旧内容作为第二页的新结果；后续分页仍检查权限与取消。各成员共享当前聊天的读取缓存，不跨账号/聊天持久缓存。
- 原成员交接改为紧凑字段/日期/单位/原文证据 ID/来源/缺口，未降低已有证据上限；桌面知识与执行历史准备并行，不丢弃记忆。后台暂停/恢复沿用原权限重新绑定与副作用账本，新增计时投影区分实际运行和段间等待。
