# Melo 架构改造与性能验收

日期：2026-10-13。用户授权整组工作，保持现有交互和本机数据格式兼容。

## 实现范围与边界

1. **状态常驻**：按规范化 home 缓存已提交快照，最多 8 个 home。读取不占用写队列；消息正文按访问复制，调用者不能修改内存权威状态。只保存变化的聊天，先写检查点，再以清单原子落盘为提交点，最后发布内存状态。失败保留旧版本。清单指纹和检查点失效版本检测外部改动，30 秒周期刷新磁盘技能。冷启动仍加载历史，常驻内存占用随历史增长，正文尚未改成分页存取。
2. **后台增量索引**：生产服务在独立 worker 中按聊天内容身份更新。清单修订号承担持久待处理记录，崩溃后重放，成功后才更新索引回执。合并积压提交、失败退避重试，原始消息已先保存。保留 memory_hits、用户编辑和提升事实；删除来源聊天后隔离相关事实，管理界面仍可查看。记忆页显示后台更新、暂缓重试和已追平。维护命令未注册 worker 时保留同步路径。
3. **局部传输与渲染**：新客户端发送 bootstrap 基准令牌，服务端返回修订号与变化字段；旧客户端或过期基准自动使用完整响应。基准只保存字段哈希，按 home 隔离并限制容量。前端按请求捕获基准并拒绝旧修订覆盖；无关的后台更新保留当前页面节点、焦点和草稿，继续使用既有流式气泡和键控 DOM 更新。后端仍组装 bootstrap，尚未将所有接口改为独立实体查询；工作区扫描用文件监听和短 TTL 缓存减少。
4. **依赖分层**：纯实体定义进入 domain，持久化辅助进入 persistence，界面组装和技能扫描归服务层，派生记忆归 memory。旧模块保留转发入口。移植只调整 import 路径，函数体哈希一致。静态循环从 3 组降至 0；gate 禁止 domain 反向依赖运行时、state 直接依赖业务服务、config 依赖执行客户端。动态 import 不在静态无环结论内。
5. **声明式路由**：核心、业务和语音路由使用 method/path/auth/handler 同源声明；清单自动导出、重复路由拒绝启动、写请求先过来源检查。手机同步的令牌校验及执行记录的路径安全检查继续使用专用入口。
6. **共享协议**：schema 生成 JS 和 Swift 的结构、标识、长度、修订号和数量约束；37 个共用样例覆盖 Unicode、非法路径、重复身份、URL、提醒 ID、任务和消息。日期、因果合并和业务语义仍分别实现，使用相同样例核对。UTF-16 的既有预算使用扩展关键字，区别于标准 JSON Schema 的字符长度。协议保持 version 1。
7. **自动 gate**：发现 src、desktop-ui、mobile-sync、scripts、ios/Tests 的所有 .test.js，使用隔离 home；排除必须有原因和到期时间，本轮排除为 0。浏览器、Swift、打包、安装和启动仍是显式阶段，生成文件漂移与依赖方向也进入 gate。

启动时的可选记忆模型初始化已移到后台。HTTP 服务不等待模型预热；关闭应用后，迟到的初始化结果会立即停止。退出窗口时先等待本次服务释放资源，超过六秒才结束无响应的自有子进程，避免立即重开时遇到残留锁。原生验收按当前五个神经模块检查可见范围，验收退出不受日常“关窗后留在后台”的偏好影响；角色设置验收先点击编辑，再保存，不再误用旧版界面假设。

## 基准口径

隔离临时 home，64 个聊天，每个预置 20 条消息，闲聊、短问题、长材料、群聊各 50 轮。使用真实状态提交、检索和 bootstrap，回答模型与 embedding 是确定性桩。这些数字衡量 Melo 本地开销，不代表真实模型、网络或设备速度。同机存在其他测试负载，不能视作严格控制的微基准。

复现：`npm run bench:turn -- --rounds 50 --chats 64 --out /tmp/melo-bench.json`。用 `--sync-index` 对比同步索引路径。完整 P50/P95 和计数：[基线](performance/2026-10-13/baseline.json)、[改后](performance/2026-10-13/final.json)。

基线的 model.first_token 包含准备阶段；最终代码将该范围更名为 turn.prepare_to_first_token，并单独记录请求到首片段的 model.first_token，两者不可混比。计时事件使用 execution_event 的 performance 类型；启用 MELO_PERF_LOG=1 可保存本机调试日志，不记录提示词、输出或密钥。独立 worker 的索引耗时记录在修订回执和记忆状态中，不归算为某一轮回答的模型耗时。

闲聊 50 轮的 embedding 调用为 0，回答桩调用 50 次。最终复测中，后台索引在最后一笔提交后约 45 毫秒追平；保存计时不包含后台索引的总成本。重复长文本的 FTS 条件已去重并限制为 128 个，保留长输入头尾。
