# iPhone 系统数据工具（日历 / 提醒 / 通讯录 / 位置）

2026-10-16，Claude 实施。用户要求手机端接入苹果系统数据。分支 `claude/ios-device-tools-20261016`，基于 `411cb42`。

## 行为边界

- **默认全部关闭。** 设置 > 手机数据里按类型开启，开启时立即申请 iOS 权限。开关只存在本机 UserDefaults（`deviceDataEnabledKinds`），**不进同步协议**，也不归属 Agent 能力范围（这是设备数据授权，不是电脑执行能力）。
- **只在 Codex 登录的对话中生效**（Responses 协议的原生 function call）。API 连接（chat-completions / Anthropic）这一轮不提供手机工具；图片生成请求也不提供。
- **读取**（列日程、列提醒、查联系人、读位置）：开关开启 + 系统授权后直接执行。
- **写入**（新建日程、新建提醒、完成提醒）：每一次都弹系统确认框，用户点"允许"才执行；拒绝、取消发送、后台到期都按拒绝处理，数据源不会被调用。
- 参数先校验再询问：日期格式、结束早于开始、超过 92 天的范围、不存在的提醒 id，都会在弹窗之前被拒绝。
- 每轮最多 8 个调用，一次回复最多 6 轮；整批调用先校验 call_id，再依次执行。超过轮数直接报错，不保存半截回答。
- 协议做法与桌面 `src/tools/functionCalling.js` 一致：请求带 `include: reasoning.encrypted_content`，下一轮原样回传上一轮输出项，再追加 `function_call_output`。
- 每次调用写入执行记录（stage `device:<call_id>`，只记"已读取 N 条 / 用户已拒绝 / 执行失败"，不记数据内容）。
