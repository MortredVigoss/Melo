范围：10-17/18 三批方案 + 网页工具落地后的全部新代码（aec8f3c…55091d3），五路并行只读扫描：工具调用线、长对话/存储线、记忆线、iPhone、桌面 UI 与 runner 胶水。每条都读过真实代码路径，标 **[probe]** 的用沙箱脚本复现过。未改任何产品代码。

## 0. 一页结论

- **P0 1 条**（iPhone `open_url` 的 `page` 参数可被模型触发整型溢出崩溃）。
- **P1 15 条**，集中在四处：① 执行器把 B1 的 `status/code` 丢了（空结果又变成"成功"，grep/glob/search_history/read_history 全受影响）；② 两个 SSRF 守卫都只查首个 URL、不查跳转/私网形态（桌面 `web_screenshot`、手机 `WebPageText`）；③ 后台预压缩用过期快照把 `toolGroupsActivated/attachmentsExternalized` 写回去（A2"只增不减"被打破、附件迁移标记丢）；④ 手机侧截图尺寸无上限（Anthropic 直接 400、图片库拒存）、`onObservation` 跨线程发布、`section/bookStatus` 未建模导致同步永不收敛、预检预算漏算摘要与日期行。
- 另有几处是**老 bug 被新代码放大**：补充消息不进 `blocks`（模型和 UI 都看不到补充）、压缩熔断从未持久化、`compact:running` 没有终止事件。
- 新代码的测试大多绿是因为 mock 掉了出问题的那一层（执行器归一化、playwright、WKWebView、后台压缩与并发写）。下一轮每条修复都要配一个穿过真实层的测试。
