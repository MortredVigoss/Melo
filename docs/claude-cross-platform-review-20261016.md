## P1：首次加载时会把新授予的设备权限误当旧数据，自动授给 Melo

位置：`ios/Melo/DeviceTools.swift:97–103`；实际入口 `ChatStore.swift:244`、`:428` 与 `DeviceDataSettingsView.swift:60`。

复现顺序：全新设置（或升级时尚未完成此迁移）→先在“设置 > 手机数据”开启通讯录→尚未给任何 Agent 授权→首次发消息或进入 Agent 页。`PhoneAgentPermissions.load` 只判断迁移标记是否缺失，将此时的设备开关当成旧权限，自动加入 `grants["melo"]`。应用启动时没有提前建立迁移边界，因此也会复制本次刚开启的权限。

隔离探针使用唯一 UserDefaults suite 和 FakeSource，实际得到：`agentGrant=true, reads=1, ok=1`。对照组先加载空权限、再打开同一个设备开关，得到 `agentGrant=false`。两个操作顺序本不应改变是否需要 Agent 独立授权。设备系统权限仍须允许；问题发生在新增的 Agent 授权边界，而不是绕过 iOS 系统权限。

建议：在启动/升级阶段、用户能够修改设备开关之前，一次性确定并执行旧配置迁移；新安装直接标记已初始化，不能把之后新开的设备权限再次当历史授权。测试应覆盖两种首次操作顺序及真实旧数据升级，证明新开设备开关之后未授权 Agent 的读取计数仍为 0。

## P2：全局开关关闭时，界面也禁止撤销已有 Agent 授权

位置：`ios/Melo/DeviceDataSettingsView.swift:72–78`。

复现顺序：给某 Agent 授予日历→关闭设置里的日历总开关→打开该 Agent 页面。开关仍显示已开启，但 `.disabled(unavailable)` 将整个 Toggle 禁用，用户无法撤回这个 Agent 的授权。之后若为另一个 Agent 重开日历总开关，前一个 Agent 的旧授权也会恢复生效。

源码对应状态探针结果：`toggleOn=true, toggleDisabled=true, reenabledGrant=true`。本轮没有操作实体手机或宣称实机点击验收。

建议：设备总开关关闭时只禁止新增授权，始终允许撤销已有授权；保存后即使重开设备总开关，该 Agent 仍应被拒绝。补这一条 UI 操作和持久化/执行计数回归。
