1. 用隔离数据复现提醒同步、删除复活、501 个聊天、超长消息、任务恢复版本冲突；缺失消息时间已经有确定性回退，补回归而不重复改造。
2. 协议保留 v1 正文兼容，增加持久化 `deletedChats` 删除记录，删除优先且不按时间复活；桌面、独立服务、手机及本地恢复文件共同实现。旧服务不回传删除记录时明确阻止假成功。旧提醒 ID 保持身份，只对消息 ID 兼容 `reminder:` 前缀，新提醒使用下划线，并保持再次送达幂等。
3. 取消正文快照中 500 聊天 / 单条 200000 字符的重复限制，用已有 8 MiB HTTP / 服务存储容量统一约束，不截断正文或静默丢记录；超容量明确返回 413，保留原数据。任意损坏 JSON、冲突 ID 仍拒绝覆盖。分页属于另外的容量扩展，不以本轮宣称无限同步。
4. 手机发送状态与自动同步解绑；同步失败只更新同步状态，手动同步仍可报告错误。用慢同步运输桩验证回复后可立即再次发送、取消不会取消同步。
5. 历史按连续完整轮次和保守字符预算挑选；超长本次输入在发送前解释并保留草稿；识别上下文超限服务错误，不能把所有 400 都误称为上下文错误。
6. 修复无 runId 的任务恢复版本与时间；语音只响应中断开始通知。补 Swift / Node 回归，核对现有图片与同步测试。
7. 更新共享神经场景包、编译 iOS 并核对产物；记录协议回归、原生模拟器、签名、真机、真实服务验证各自的完成范围。

## 交付与升级边界

- 本轮未签名 / 覆盖实体手机，未重启用户当前桌面进程或部署远端同步服务。要在真实多设备环境生效，桌面服务、独立同步服务（如使用）及 iPhone 都需使用新代码。
- 新客户端遇到旧服务丢弃删除标记会报未确认删除，保留本机数据，不声称同步成功。旧客户端忽略返回标记时可能仍显示旧聊天，但更新后的服务与桌面不会让它重新出现；须升级旧客户端。
- 总量 8 MiB 限制仍在，未做分页同步；任意损坏数据或同 ID 内容冲突仍会停止合并，避免覆盖原始记录。文本预算为保守估算，不能保证适配所有供应商的上下文窗与图片计费规则。
- 本轮测试未调用真实模型、账号或云服务；上一轮图片功能仍保留，真实图片服务验收边界见 `docs/ios-image-workflow.md`。原先偶发进程退出未在本轮定位，不标记已修复。
- `deletedChats` 是共享语义，不只是手机 UI；主线继续修改资料导入、状态恢复、删除入口时必须保留此字段，不得使用“快照缺席”当作删除，也不得剪掉旧删除记录。
