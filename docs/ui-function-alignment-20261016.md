用户转交 UI 审核，要求核对并修复已确认缺口；删除聊天规则明确为每次询问是否同时删除文件。未做选择前保留文件。实际基线 `eecc8a9`；隔离分支 `codex/ui-function-alignment-20261016`，共享源码现有 WIP 保留。

## 实施顺序与验收

1. **聊天文件与生命周期**：文件面板、预览和 Finder 跟随当前聊天实际工作区；普通聊天提供可见文件入口。浏览不创建空目录。删除前返回文件影响预览，用户选择保留或同时删除；只允许删除由 Melo 分配的聊天目录，绝不删除项目目录、任意用户路径或跟随符号链接。手机同步/旧客户端删除留下待处理记录，在电脑询问去留；历史遗留目录可在存储管理查看、打开和清理。验收跨项目/无项目切换、取消/保留/删除、远端 tombstone、冷启动恢复、路径替换与正在执行时拒绝清理。
2. **Agent 能力配置**：技能、MCP、连接器和委派目标改成名称列表勾选；保留已有但当前不可用的 ID 并明确标记，避免编辑时丢权限配置。未迁移状态在列表和编辑页可见，并默认展开能力区。验收空列表、多选、存量未知 ID、项目收紧和迁移确认边界。
3. **能力与旧接口**：移除全局本地文件/命令 UI 开关的阻断作用，模型上下文按 Agent 能力决定。用户文件浏览与 Agent 执行能力分开；关闭 Agent 能力不隐藏已有成果。核对路由的 CLI/手机/后台调用，不因无桌面入口就删除业务服务；确认为退休的 HTTP 写文件/执行入口返回明确 410，活跃任务入口继续执行能力检查。用拒绝计数器证明无执行副作用。
4. **管理入口**：补外部连接器新建/修改/删除及资源、提示词、工具操作；补 MCP 按保存配置单独重连、会话授权查看/撤销、技能导入/写入磁盘/重载/重新扫描建议。输出返回值和失败保留输入，不添加空按钮。补相关缺失文案与五语资源。

## 边界与证据

- 新入口沿用现有暗色界面、显式保存与错误反馈；配置、用户内容和账号不迁移。
- 文件清理只处理明确选择的本机目录；同步本身不携带删除文件的隐式授权。项目目录始终保留。
- 所有网络/工具验收使用本地夹具；不连接用户外部服务、执行真实远程工具或改变真实会话授权。
- 每阶段记录实际专项/浏览器结果，最后共享树日常 gate；不自动 git pp 或推送，不将日常检查称为完整安装或实体手机验收。
