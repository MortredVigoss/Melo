## 1. 确认的问题

### R1 / P2：新建 Agent 已提交但页面重载失败，会自动进入旧 Agent 的编辑状态

- 位置：[`desktop-ui/bootstrapPatch.js`](../desktop-ui/bootstrapPatch.js) 的 `settleCommittedSave`（56–61 行）；调用链为 [`sharedApi.js`](../desktop-ui/sharedApi.js) → [`features/agents/controller.js`](../desktop-ui/features/agents/controller.js) 的 `handleCreateCustomAgent`（323–328 行）。回退逻辑在 `6d5e00e` 引入，后续拆分沿用。
- 条件：用户正在查看 Agent A；点击“新增 Agent”；后端创建 B 并提交，但构建 bootstrap 失败，返回 `{ok:true, receipt, bootstrapError}`；随后 GET `/api/bootstrap` 也失败。
- 原因：共享请求层把旧 bootstrap 作为普通成功结果返回，丢失“已提交、页面未刷新”状态和 `receipt.agentId`。创建控制器照常应用旧数据，并对页面上找到的第一个 Agent 表单调用 `beginFormEdit()`；该表单仍属于 A。
- 影响：B 已存在，但用户接下来填写并保存的是 A。旧 Agent 的名字、人设、能力等可被误改；再次点击新增也会创建额外 Agent。只提示“已保存”不足以保证当前表单对应新实体。
- 浏览器复现：隔离 home 初始 4 个 Agent、当前只读 `research`；点击新增后服务器增加到 5 个，新增 id 为 `custom-agent-1`，界面自动解锁的表单 id 却为 `research`。随后输入 `Review intended new agent` 并保存，实际 POST 的 `agentId` 为 `research`；服务器上 `research` 被改名，新 Agent 仍叫 `Custom agent 1`。无页面脚本异常。
- 注入边界：使用真实 Melo 测试服务、真实 Chrome 和真实创建/更新接口；Playwright 仅将创建接口的成功响应替换为服务端已经定义的提交后回执，再让页面 GET bootstrap 返回 503。没有破坏配置文件或修改用户数据。

修复建议：共享请求层保留提交回执和刷新未完成的显式状态，调用方不能将旧快照当成新建结果。创建页只有在返回快照包含回执指定的 Agent、且表单 id 匹配时才自动编辑；否则展示“已创建，等待刷新”，提供只重读页面数据的恢复入口。更新流程也应保留已保存的值，直到取得相应新快照。不要重新发起已经提交的 POST。

验收至少覆盖：创建成功但两次读失败时旧 Agent 保持只读；恢复读取后编辑正确的新 Agent；整个恢复过程只创建一次；已有 Agent 保存和项目创建在相同故障下不丢失回执、不误报失败或诱导重复创建。

证据：本地 `.tmp/claude-architecture-review-20261019/committed-create-repro.mjs` 与 `committed-create-result.json`。复现脚本断言的是当前缺陷确实存在，不是修复后的验收测试。

## 4. R1 修复（用户随后授权）

- 共享请求层收到提交后回执时，只通过 GET 读取新快照；连续失败不再返回旧快照。原命令保持等待，保留表单值和忙碌状态，页面持续显示“已保存，等待刷新页面”。刷新按钮只读数据，单次读限时 15 秒，同一回执不能并发重读，也没有自动循环重试。
- 快照修订号必须达到提交回执的修订号；本次创建的 Agent id 经本地 WeakMap 保存，不改变 HTTP/同步/存储协议。只有存在对应 Agent，且当前全局表单 id 与其匹配时，才自动打开编辑。并发导航或项目覆盖表单不会误获编辑状态。
- 五条回执接口的相同进行中请求共享结果；项目创建增加忙碌防重入，读取未恢复前保留输入并禁用提交。Agent 保存也在取得新页面数据后才清理草稿。
- 新增真实浏览器故障测试：Agent 创建后连续读失败、再次刷新失败与恢复；Agent 更新后保留已提交人设；项目重复提交与恢复。检查服务器实体数量、实际写入目标、旧 Agent 配置不变、整个恢复阶段 POST 仅一次。
- 单元测试覆盖旧快照/无效 200 被拒、重复 POST/刷新去重、独立回执分别恢复、普通提交错误仍可重试、警告与身份保留、异步导航及项目覆盖不被误编辑。
- 新提示进入共享五语目录并经生成器同步 `ios/Melo/Localizable.xcstrings`、Scene bundle/manifest。只更新生成的语言资源，没有修改 iOS 业务逻辑、同步协议或用户数据。
- 完整日常检查另暴露旧并发测试的顺序假设：两个读取工具都已重叠执行，但异步准备使第二个先启动。测试改为接受任意读取启动顺序，仍要求两次读取在任一次结束前启动、峰值并发为 2，写入严格按原顺序串行；没有改变执行器行为。
