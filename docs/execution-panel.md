# 真实执行驱动的三维任务面板

2026-10-07，实施方案与交付说明。

## 依据与选择

工程已有本地 Three.js r184、透视相机、聊天 SSE、工具执行器、原生 Codex 搜索/生图流、可点击网页引用及附件卡片。复用这些能力，不引入 CDN、额外生图或第二套引用协议。

独立任务面板放在聊天滚动区与输入区之间。五个区域为网页检索、分析与计算、文件与代码、工具调用、模型与成果；没有记录的区域只保留氛围。工具调用汇总所有真实调用，功能区域保留同一记录的归属；模型与交付阶段单独计数。模块不代表模型内部思维。

## 先补事件，再实现空间

1. 工具执行器在实际开始运行、等待许可及结束处发出逐调用事件，遵循原有串并行调度。整批请求只表示排队，不表示所有调用已经执行。
2. 原生搜索连接 output item、search/open_page/find_in_page 和来源记录；未提供读取范围时标注未知。实际保存图片后才发布候选，不发送图像字节到场景记录。
3. 每轮独立运行标识、单调序号、可持久化快照。失败和取消也保存，回看通过只读接口加载，不重新执行任务。
4. 全部真实来源统一按问题、追问上下文、实际搜索词与标题、网址、摘要的文本匹配和服务排名排序，默认取前五个，展开总共最多十个。引用单独高亮，不保留名额，也不排除引用来源。排序是启发式相关性，不是概率或语义评审。十个以外仍保留记录，回答引用仍可从聊天访问。读取摘要、提取正文片段、范围未知分别标注。
5. 图片保留实际成功保存的候选。默认选一张，明确数量则按请求数量选择；替换仅改变本轮已存在的展示结果，不生成额外图片。

## 视觉与交互

Three.js 透视场景中放置不同 z 深度的区域、神经节点和曲线。点击区域移动相机位置及观察目标，来源逐层向前展开；标签使用投影到屏幕的可访问 DOM，避免文字在透视中失去可读性。

按用户最新澄清，主体采用与背景一致的开放式神经线网：中央由少量细线和节点连接，七组细长分叉以深紫色、节点柔光和轻微呼吸区分，不保留实心表面或球形核心。线束通过坐标变形实现伸展、弯曲与位置跟随。每个真实并行活动区域保留主体，任务结束冻结爬行姿态，低强度网络脉冲独立持续。

成果立即进入已有聊天渲染，短暂、不可拦截点击的光点/卡片同步飞向真实引用、答案或附件位置。结束后自动折叠；回看保留模块、来源、成果、选择与主体终态。隐藏时停止绘制，低性能或无 WebGL 时保留全部可访问信息。

## 现有接口边界

1. 旧任务没有逐调用场景记录：只提示未保存，不通过回看重跑补记录。
2. 原生搜索本次只返回 URL 清单，部分网页没有标题、摘要或逐页读取事件：标签使用真实 URL 路径，悬停明确“页面标题未提供”，读取状态标注“未记录页面读取”。需要供应商返回 `title`、逐页 `open_page/find_in_page` 和读取范围/字符数，才能显示更完整信息。不会把 URL 出现在结果中说成已读全文。
3. MCP/软件调用若只返回自由文本，只能展示调用状态与截断的实际输入输出。需要结构化 `{url,title,reading,characters}` 来源和 `{id,kind,url,path}` 已保存成果元数据，才能进入相应候选节点；本地路径只在通过 Melo URL 签名验证后允许续签。
4. 没有供应商进度百分比、内部推导、额外候选及采用/淘汰理由时均不补造。相关性目前是问题词匹配和服务返回排名的启发式排序，不宣称语义评审。
5. 神经主体使用程序化细线、发光节点、伸缩与位置跟随，参考视频的分层空间与运动风格；并非逐帧复刻或物理软体仿真。后台真实并行区域同时保留主体。
6. 无 WebGL 时回退可点击的记录布局；降低动态效果设置暂停氛围运动。面板关闭或页面隐藏停止 GPU 绘制，原子入口在页面可见时持续运动。

## 2026-10-07 用户反馈后的核对与修复

实际问题来自同一轮 `bash` 检索：Google 返回 JavaScript 提示页，Bing 返回 RSS；旧观察器把所有 bash 归入工具连接，并在提取来源前截断输出到 2,200 字符。现在单一字面量 curl 请求在运行时进入网页检索，RSS / 支持的 Google、Bing HTML 结果在摘要截断前保存为独立来源。bash 内部许可等待也单独发事件，许可通过前不会播放执行动作。未改变许可规则。

回看旧场景只解析保存过的输出：完整 RSS 条目直接恢复；被截断的长 URL 前缀只有与同一轮唯一最终引用匹配时才能恢复完整链接，缺失正文和摘要仍为未知。最终引用没有访问证据时仅作为引用记录，不标为已读取。原事件时间、结束状态与图片选择保留，读取历史不会产生网络请求。

在用户反馈的真实对话中恢复了 5 个搜索条目和 1 个引用入口，网页检索显示已完成；抖音结果按追问上下文排序在前列。前五条卡片突出，展开后的其余候选弱化但仍可点击；所有来源独立保留，展示最多十条。悬停可查看完整标题、URL、读取与引用状态；检索调用条单独说明服务返回情况。相关性按文本匹配和服务排名排序，不是概率。

新主体已在 Chrome 和原生 Melo 中目视核对。真实任务来源卡片无重叠；点击未引用的候选成功打开原网页。143 项隔离回归通过，包含本地 HTTP fixture 经真实 curl、原有许可门、执行器、事件和 sidecar 的完整链路，验证 24 条来源保存且界面仅显示 5 / 10 条。没有为了修补旧历史重新检索或调用付费模型。

边界：任意 Python / Node 脚本、复合 shell 命令及自由文本 MCP 输出不会仅凭出现 URL 就归因成网络访问；这些调用需要补充结构化网络请求和来源事件。当前 HTML 提取支持已知结果结构，结构改变或提示页会显示未提取到条目，不伪造来源。旧场景没有保存下来的摘要、读取范围不能完整恢复。
