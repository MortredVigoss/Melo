# 回复进行中：可改设置、可中途补充、主界面显示过程（2026-10-17，Claude）

用户反馈：回复进行中不能换 Agent、换模型、上传图片；希望像 ChatGPT / Claude 那样中途补充要求；希望主界面（不只是神经网络场景）实时显示“现在正在做什么”，长任务走偏能及时发现。

## 现状（读代码确认）

- 手机：回复进行中，该对话的 Agent / 团队 / 模型 / 项目按钮、照片 / 视频 / 图片选项、语音按钮全部禁用；存储层也拒绝回复中切换 Agent 和模型。进行中只显示一行状态文字。
- 电脑：回复进行中 Agent 选择被禁用，再次发送被忽略；过程只在工具调用时短暂显示“药丸”，结束 1.8 秒即消失。服务端结束时不会覆盖对话的 Agent，所以放开选择是安全的。

## 方案

| 顺序 | 改动 | 平台差异 | 验收 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 回复中可改 Agent、模型、团队、项目，可添加图片 / 视频 / 语音输入；全部从下一条消息生效（本轮在开始时已取定） | 两端 | 进行中切换后本轮回复仍按原 Agent 署名，下一条按新 Agent | 已完成：手机模拟器验收；电脑浏览器测试确认回复中 Agent / 语音可用 |
| 2 | 中途补充：回复中输入框仍可发送，作为对当前问题的补充 | 手机：当前请求停止，问题末尾追加“补充：…”后立即重新开始（手机多为单次请求，无法插入半途）。电脑：在下一步模型调用前插入（保留已完成的工具步骤）；若本轮已没有下一步，结束后自动作为下一条消息发送 | 手机：补充后只保留一条回答、按补充内容；电脑：工具循环中补充被下一次请求收到 | 已完成：手机模拟器验收；电脑执行器测试（下一次模型请求带补充、已完成工具保留）+ 浏览器测试（单步回复结束后补充作为下一条发送） |
| 3 | 主界面过程：回复中在对话里列出最近的步骤（进行中 / 完成 / 失败 + 简短说明），与任务空间同源 | 两端 | 模拟器 / 浏览器实看；步骤来自真实执行记录 | 已完成：模拟器与无头浏览器截图，步骤在可视区内 |

## 结果与边界

- 补充失败或手动停止时，电脑把补充文字放回输入框，不会丢；新对话的第一条回复期间补充会在结束后作为下一条发送（服务端那时还没有对话编号）。
- 补充写入记录：电脑把本轮用到的补充附在问题末尾（“补充：…”），手机重新开始时同样写入问题。
- 浏览器测试覆盖两种电脑情形：工具步骤中补充 → 同一轮下一次请求带上工具结果与补充、问题记录末尾写入“补充：…”；单步回复中补充 → 结束后作为下一条发送。
- 未验证：真实模型下补充后的回答质量；实体机。
