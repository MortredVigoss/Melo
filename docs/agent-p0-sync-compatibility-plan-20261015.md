## 推荐决策：保留旧端兼容，不强制同时升级

P0 保持 v1 传输契约：四个旧人设字段各自不超过 50000 UTF-16 单位。桌面和新版手机内部仍保存一份 canonical instructions，旧字段仅在同步边界转换，不恢复多个人设写入来源。

1. **分离内部人设与 wire 格式。** 不再在 v1 校验/合并时把四个字段合为超限单字段；旧服务和离线旧手机看到的仍是原 v1 合法形状。
2. **只有无损转换才发送。** 对原有四字段保留可校验的传输映射，绑定 canonical 内容指纹；未编辑时准确往返。编辑后重新转换并验证“编码→解码”内容一致和字段限制，不能把任意长文按字符切成四个人设段落。
3. **不可表示的新版文档保留待同步。** 保留本机全文、草稿和上一份已同步版本，明确显示“此 Agent 的新版人设需要兼容协议升级，尚未同步”；不伪造同步成功，不覆盖远端旧版本，不让该记录阻断聊天/任务等其余合法数据同步。项目级人设同样处理；没有可用旧记录的新 Agent 或引用它的配置要明确标为待同步，不能造空人设。
4. **不改变冲突和删除语义。** 不给不同内容复用同一向量时钟，不因投影或失败自动推进远端确认，不自动解决离线并发冲突；重试不反复制造新版本。对同一次编辑分别测试本机保存成功和同步状态。
5. **新版完整人设协议在 P4 显式协商后启用。** 服务和客户端均确认支持新版时才使用新的单字段上限；无能力声明按 v1。兼容探测失败保留本地待同步数据。升级顺序为服务先支持两版，再逐台升级客户端；旧设备重连仍能处理 v1。协议版本、记录投影和失败恢复由共享契约与两端测试锁定。

### 兼容矩阵

| 组合 | P0 行为 | 不可无损表示的新版人设 |
| --- | --- | --- |
| 旧桌面 / 旧服务 / 旧手机 | 维持原 v1 | 不引入新格式 |
| 新桌面 / 旧服务 / 旧手机 | v1 人设往返，其余数据照常同步 | 本机全文保留，标记待同步 |
| 新手机 / 旧服务 / 旧桌面 | 同上，旧四字段本地组合展示 | 同上 |
| 新桌面 / 新服务 / 旧手机 | 服务保留 v1 兼容，不假定离线设备已升级 | 同上 |
| 全部新版 | P0 仍按 v1；P4 协商成功后才开新版完整协议 | 未协商前保留；协商后完整同步 |
| 旧手机离线编辑后重连 | 保留合法旧字段和冲突版本，显示需人工处理的并发改动 | 不覆写新全文或截断 |

P0 不承诺让旧版客户端理解其原本不支持的任意超长单字段；承诺旧合法数据无损、普通同步不中断、新数据不丢失且状态可见。
