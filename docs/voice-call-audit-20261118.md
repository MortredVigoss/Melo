# 实时语音对话优化建议 · 2026-11-18

审计基于本机 master 的 a3f49ce6，覆盖 Mac 桌面和 iPhone 的通话入口、声音引擎、回复事件、分句和播放。建议沿用已经选定的级联方案。首要目标是每句话只在所属通话播放，用户开口时能可靠接管，核验完成后尽快听到第一句有效回答。

普通文字聊天在桌面有增量显示，iPhone 的 ChatStore 有临时回复草稿。语音把答案送入扬声器有自己的交付边界。需核验的事实、工具结果和操作完成声明，应当只读已经获准交付的内容。若希望提前播报，可先试“在核验期间仅为候选首句准备音频”，仅在最终首句、口播规则、Agent 音色和轮次全部匹配时播放。额外合成费用、丢弃率与第三方音色的草稿披露须单独评估，首期优先本机音色。

## 落地与验收

1. 先修旧会话迟到事件和回声误判。增加快速重拨、换聊天、同聊天重拨、重开后迟到审批、连续打断以及半双工测试。验收要求旧会话向新播放器提交 0 句，迟到结束事件更改新通话状态 0 次。
2. 在两个宿主记录单调时间戳。分别标出用户话音结束、转写提交、首个屏幕文字、最终回答获准、首段音频交给播放器、首个可听回答。审批或“我查一下”独立计时。软件播放事件早于扬声器实际出声，做一次声学对照校准。仅记录时长和原因码即可。
3. 桌面系统音色复用共享分句规则，服务端音色按播放进度补充队列。在相同模型、音色、网络与测试语句下，分别覆盖 Mac / iPhone、扬声器 / 蓝牙、短问答 / 搜索任务。每组至少 20 轮，报中位数和 P95。初始工程目标是定稿到首句可听的中位数减少 25%，有效插话到静音的 P95 小于 400 ms，且误断句率、漏停率和回声误触率均不升高。首轮采样后校准目标。
4. 只有当首句仍主要耗在等待核验，且本机音频准备占足够比例时，再评估候选首句预合成。耗时若主要在模型或工具，应回到对应阶段优化。首句和整轮完成时间分开报告。
