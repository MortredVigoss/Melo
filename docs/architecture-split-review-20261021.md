## 尚未收紧的边界

1. **聊天视图与控制器存在循环。** `controller.js:26` 导入 `viewThread.js`；后者导入 `viewComposer.js` 和 `viewMessage.js`，这两个视图分别在第 21 / 17 行从 controller 取附件和输入辅助函数。完整静态图得到这 4 个模块组成的 1 个循环组。尚无本轮运行时故障复现；属于明确的架构债务。应把纯展示辅助函数移到叶模块，再消除反向依赖。
2. **中央状态和聊天控制器仍较重。** `app.js` 有 198 处可被现有正则识别的 uiState 写入；聊天 controller 1,621 行，CHAT_CONTEXT 有 56 个注入项。名称显式化已改善可读性，但发送、附件、流式显示、语音与壳层回调仍相互牵连。
3. **业务层仍依赖整页组装。** 11 个业务服务直接导入桌面 bootstrap，42 个模块直接依赖全状态 stateStore。数量本身不是错误；前者应继续按已有提交回执模式迁移，后者需逐功能明确读写入口，避免无差别包一层空服务。
4. **手机协调层尚未完成拆分。** ChatStore 同时持有发送、执行记录、保存、审批及同步等流程；应按运行生命周期、持久化、同步边界拆分，保持同一运行预算、取消和数据回滚语义。
5. **约束不够完整。** `check-dependencies.js` 默认只检查 src，当前 445 模块 / 0 循环且层次约束通过；扩大到 src、desktop-ui、mobile-sync、shared 后是 619 模块，发现上述前端循环。`npm run boundaries` 仍是报告；虽有禁止新增旧 bootstrap 依赖和中央 switch 冻结测试，但宽上下文与 turn 的 JSDoc `*` 尚无类型检查约束。
