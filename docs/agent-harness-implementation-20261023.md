## 与来稿合并后的具体取舍

- 采用取消普通首步必搜与保留候选回复；导航前的搜索/目的地依据仍是执行约束。
- 新目标检查使用实际工具观察 ID 和逐项交付评估，接纳无 URL 的本地结果。没有把旧二元词组阈值从 0.75 降到 0.5 来制造“已完成”；旧回执算法保留给无新目标状态的历史/独立调用。
- 只读、计算、写入按动作分类，不能拿 `requiresPermission` 当副作用类型；MCP 只读声明仅帮助分类，不授予权限或豁免审批。
- 对普通稳定知识允许直答；对明确实时事实或已执行工具的任务，缺少最后交付时有界补做。检查不可用时保留回答并说明完成情况未确认，不无条件显示“已完成”。
- 手机宿主本轮一起接入，避免先只修桌面留下长期差异；智能路由及记忆配置维持单独设计边界。

## 已实施的行为

1. 每轮保留原始目标、运行中补充、缺口、依据 ID、纠偏次数；最终随 `completion.task` 保存。显式“继续/重试”从对话历史还原目标，不自动恢复旧轮的外部操作。
2. 工具返回仍可继续调用其他工具；取消普通检索的首步必搜，保留导航的目的地依据要求。候选答案进入同一模型/连接的无工具检查，模型指出公开可查的缺口时回到原循环。
3. 检查与补做占用现有轮数、token 和时间预算，最多两次纠偏；检查无工具、无原生搜索/生图能力。修正期间相同参数的已成功写入/未知副作用不重放，原权限与审批不变。
4. 检查 JSON、依据 ID、要求覆盖不合格时保留已有回答，回执说明未确认完成；取消仍传播。普通自包含且未调用工具的问答不增加检查请求。被拒绝的工具尝试也不能被当成普通闲聊直接标完成。
5. 本地日历、历史、知识、计算、文件读取可作为交付依据，不要求回答原样写出 URL；事实正确性与交付完整度分开。新回执的 `supported` 表示根据实际返回材料检查了交付，不能当作独立事实验证。
6. 桌面主聊天、委派、技能及 iOS/Android 共享判断；团队汇总保留成员回执，成员未完成或失败时不能被汇总文字提升为全部完成。

证据和候选内容有长度上限；超长目标/候选不截尾后宣称完成。证据预算优先保留最新结果，防止早期长网页挤掉最终天气。界面沿用执行面板，新增“核对任务交付”步骤与明确的未核对原因，无新的设置或数据迁移。
