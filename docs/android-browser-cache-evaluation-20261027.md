Started 2026-10-27, continued 2026-10-28 (Australia/Sydney). Branch `codex/android-organizer-20261026`; baseline HEAD `2bb7ffc`. This is local WIP validation, not a release or full Trace feature acceptance. No push or PR. Testing used only the Emulator; the user subsequently explicitly requested installation on the connected Fold6, recorded separately below.

## Method and evidence boundaries

- Owned persistent Android 16/API 36 AVD `Melo_Benchmark_36`, Linux ADB server port 5048, serial `emulator-5580`. No physical device is targeted. Emulator resolution 1856 × 2160 is not Fold6 posture/One UI validation.
- Real Bedrock Messages transport, `us-west-2`, model `us.anthropic.claude-opus-5-5`. The previously authorized credential is read from Emulator Keystore. Public evaluation goals only; no key in source, command arguments, output or fixtures.
- Opt-in `MobileTaskBenchmarkTest` calls production `DeviceAgent.start` or `ChatEngine.send`. It submits a natural-language goal; the test never supplies a script ID and never approves an unexpected confirmation. The actual model/registry chooses `phone_use`/`phone_workflow`.
- Before every browser attempt, load the owned static blank page on port 8893 and independently verify `Benchmark start page`; force-stop Chrome, then go Home. Both first and repeated attempts therefore start with a blank restored tab and a cold browser process. Baseline setup is outside measured wall time. Network/OS/HTTP caches are not cleared, so this is not an isolated network-cache experiment.
- Chat measurements use the debug-only native fixture Activity to provide a foreground lease, then the real production ChatEngine. This does not measure Compose input/rendering latency.
- Each run writes a new UUID `runTag` and initializing report before setup. The host rejects stale reports. Record wall time, parent/child model calls, cache ID/mode, per-action receipts and an independent final UI Tree. A failed test remains failed even if a later attempt works.
- `.tmp/benchmark-v6-*.json`, `.tmp/benchmark-v7-*.json` and paired instrumentation logs are local ignored evidence. Native Trace event/artifact archives stay local in `.tmp/`; normal task/model tool traffic does not upload Trace files.

Evidence: `.tmp/benchmark-v6-browser_article-chat-default.json`. That batch also has a separate first-attempt `foreground_window_unavailable`/SystemUI failure, not proof Chrome was absent.
- Local HTML form searches initially paused on a generic/unlabelled IME action even though this was a Search editor. No confirmation was auto-approved. Evidence: `.tmp/benchmark-v6-local_search-device-{shared-core,agent-cache}.json`.
- With native EditorInfo classification, the same form completed for both keywords, but no whole-task cache was saved because the HTML input exposed neither resource ID nor description in the old projection. Repeated runs therefore remained Probe: `shared core` **33,983 / 32,645 ms** and `agent cache` **36,279 / 34,068 ms**, nine child requests each. Evidence: `.tmp/benchmark-v7-local_search-device-*.json`. This is task success and cache failure, not cache acceleration.
- Changing the Google query to `Android EditorInfo IME_ACTION_SEARCH` matched the template and loaded correct results, but the old completion assertion referred to a particular earlier result title. It stopped at verification after **20,150 ms**, zero child requests. A second run probed successfully in **27,737 ms**, six child requests. Evidence: `.tmp/benchmark-v7-browser_search-device-Android-EditorInfo-IME_ACTION_SEARCH.json`. Parameter binding alone does not make result-dependent assertions reusable. Keep this failure explicit; do not weaken completion verification merely to claim a cache hit.

## Fixes exercised in this work

- Focus is checked before text mutation. Cached replay focuses an editable node, then re-observes and resolves fresh IDs. A rejected unfocused input is a known no-effect receipt, not pretend success.
- URI editors and registered browser address widgets can use navigation Enter/Go under task authorization. Generic form/message Enter remains guarded. API 33+ native EditorInfo is accepted only for the focused, visible selected window and matching input owner; SEARCH does not require a redundant confirmation, SEND does. Input action identity is rechecked after any approval.
- Native observations retain the accessible name from contentDescription, labelledBy or hintText, in that order. This supports stable selectors without persisting runtime node IDs or matching an arbitrary unlabelled EditText.
- Device Anthropic requests use `tool_choice.disable_parallel_tool_use=true` to match the serial observation/action executor. General Chat tool batches are unchanged.
- Model-derived inputs that are absent from the literal user goal remain fixed script literals; they no longer create orphan template parameters that can never exact-bind.
- A changing Skill Manifest changes the Anthropic system prefix. Bound thinking is dropped when the prefix/context is edited, while paired tool calls/results remain. Actual prior Bedrock 400 evidence said the system prompt differed.
- Shared Core treats an explicit phone-browser URL interaction as requiring `phone_use`; `fetch_url` remains registered for later information gaps but is not a mandatory duplicate read. Bare read-URL requests keep their fetch requirement.
- Native Engine startup no longer eagerly initializes WebView just to enable debugging. This removed an Emulator cold-start blockage; recovered app data/Keystore were preserved.

Its instrumentation log was saved, but no valid fresh result JSON was accepted. Only the owned Emulator process was stopped; Ubuntu/other user processes and the physical phone were not restarted or operated. Previously saved v6/v7 evidence survives. Do not use that stalled interval as a performance sample or claim the v8 scenario passed. JVM results before this incident: 182 tests, zero failures/errors.
