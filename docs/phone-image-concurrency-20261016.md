# 手机：图片意图、对照预览、多任务卡顿（2026-10-16，Claude）

用户反馈（0.5.22 实机）：附图并提出修改要求时，前几次常回复“缺少工具”；结果/原图对照两页图片不在同一水平线，底部“双指缩放”提示多余；同时给两个 Agent 发任务会卡，执行中界面像卡住、部分按键不能用。分支 `claude/phone-image-concurrency-20261016`，基于 `1500a2e`。

## 根因（读代码确认）

1. **缺少工具**：手机是否出图只靠正则判断。“把天空弄成晚霞”“处理成卡通风格”等不在列表里的说法会落到“看图分析”，请求里没有图片工具，模型只能说没有工具。电脑端普通对话里 Agent 仍有图片工具可调，手机没有这层兜底。
2. **对照错位**：预览页图片区域占满剩余高度；“结果”页多一行“服务返回：模型”（保存状态也可能不同），“原图”页没有，图片区域高度不同，位置随之跳动。
3. **卡顿与不能操作**：全应用同一时间只允许一个请求（单个 `sendingID`），第二个对话发送被拒，多处按钮在任何请求进行时都被禁用；Codex 回复流在主线程上逐字节读取（账号对象绑定主线程），图片回复是数 MB 数据，期间界面响应变慢；后台续行对象也只支持一个回复。

## 方案

| 顺序 | 改动 | 验收 | 状态 |
| --- | --- | --- | --- |
| 1 | 附图（本轮或上一张图）+ 祈使性要求（非提问、非看图分析、未拒绝）即判为修改；文字明确要做图即生成。普通 Codex 回复在本机允许图片时始终带图片工具（模型自行决定），说明里写明可直接调用 | 意图用例表（新增口语改图/提问不改图）；请求体测试：普通回复带 `image_generation` 且为 auto，未允许时不带；工具返回图片能保存 | 完成 |
| 2 | 预览底部信息区固定高度，删掉“双指缩放”提示；两页图片区域一致 | 模拟器两页截图比对图片位置 | 完成 |
| 3 | 每个对话独立运行：发送状态、任务、取消、后台续行、状态文案按对话分开；只禁用“当前对话正在发送”相关按钮 | 模拟器内验证：两个对话同时发送都完成，互不取消；取消一个不影响另一个 | 完成 |
| 4 | Codex 回复流移出主线程，解析结果按节流回到主线程 | 单元测试照常；模拟器实看执行中可切换页面、滚动 | 完成 |

边界：设备数据确认弹窗同一时间只显示一个；若两个对话同时请求写入手机数据，后到的一个会等待前一个处理完（不自动拒绝）。

## 验证

- 意图：共享用例新增 17 条（口语改图、提问不改图、参考图生成），电脑与手机都跑同一份；去掉“附图 + 指令”规则后电脑端 8 条失败。补上了两端原先都漏掉的“参考这张图生成…”。
- Codex 请求：允许时普通回复带图片工具（不强制动作），返回的图片会保留；不允许时不带。按对话的状态文案在回复结束后清除。24 个 Swift 套件、日常 `npm test` 通过（一次因两台模拟器占用机器导致两项桌面浏览器测试超时，空闲后单独和整套重跑均通过）。
- 模拟器：并行验证（真实 `ChatStore` 发送路径）两段对话同时回复、各自完成；停止 A 不影响 B；期间主线程最长停顿 185 ms。团队、会话、图片流程、同步审计、交互验证全部通过。后台续行验证的回归部分通过；“切到后台继续完成”这一段在模拟器上与修改前的版本一样无法完成（应用在模拟器后台被挂起），需实机验证。
- 预览：新建的 QA 模拟器上对照“结果/原图”两页，图片位置一致，底部提示已去掉。
- 未验证：真实账号下模型自行调用图片工具的表现；实机上的并行回复与流畅度；API 连接（非 Codex）没有这层兜底，仍靠意图判断。
