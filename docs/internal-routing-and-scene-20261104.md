# 对话 Agent 分工与任务空间记录

基准 889174f。桌面实际配置中，金冬天与懂王均关闭委派。模型档位只选择模型。桌面和 iPhone 已有显式团队、成员权限交集、交接与主 Agent 汇总。当时普通聊天只能直接办或显式组队。用户随后选定按需分工，落地记录见下。

## 已复现的记录断点

iPhone 的 deviceToolContext 收到 open_url 或 web_screenshot 的结果后调用 stage。ExecutionRecord.recordStage 默认写入模型模块 create。桌面与手机共用的 executionPanel 根据 operations 计算调用次数，根据 sources 显示来源。读取回调遗漏了这两项，后续供应商快照还会覆盖本机观察。

本次从工具执行后的结构化回执记录检索、手机工具和读取历史，区分实际执行与执行前拒绝，按 URL 身份合并来源。旧版回放只按已知的宿主事件 ID 分组。覆盖多页、失败、截图、重复观察及新旧记录混合，真实内容缺失时保留未知。验收包括 Swift 回执、共享界面回放和手机资源构建。范围限于任务空间，发布、安装和个人配置独立。

## 内部调度候选方案

- 按需分工（9/10）。简单对话由当前人设直接答，复合任务按依赖拆分为检索、计算、受权执行和复核。检索交接要有来源与读取状态，计算交接应有输入和结果。路由核对原始目标，按证据补缺或部分交付，由原人设回复。延迟和模型用量较低。
- 每轮启动独立路由模型（6/10）。问候与单步任务也经过路由。执行路径一致，每轮增加请求与延迟。
- 两种方案均应继承当前 Agent 权限与取消/预算，按实际成员标明执行身份，已生效的写入不得重试。外部自定义 Agent 的委派白名单仍是独立授权。本线程用户已选第一项。

## 执行器核对与推荐落点

| 层次 | 现有入口 | 需要补的行为 |
| --- | --- | --- |
| 对话入口 | 桌面 invokeModelNode，iPhone ChatStore.runTeam | 保留选中的金冬天或懂王作为对话身份、模型配置与回复者。普通请求现可在这一轮逐项分配岗位。 |
| 成员 | 桌面 runConfiguredMember、iPhone AgentTeam | 复用成员独立上下文、预算、停止和交接。内部岗位用稳定职责和工具白名单标识，禁止按显示名匹配。 |
| 主持与核验 | 桌面 runAgentTeam 和 teamCompletion，手机 runTeam | 校验原始目标的每一项。成员已查到演唱会城市，但天气仍为空时，交还检索成员继续查。到预算仍缺天气才给部分完成。 |
| 宿主差异 | Android SharedChatAgent 已按 search 操作写入网页检索 | 任务拆分协议可共享。每端先公布当前可执行的岗位；Android 原生对话本轮已接入内部岗位切换，显式团队模板仍由各宿主单独支持。 |

按需方案可用这条任务做验收：用户问“查演唱会当天气温，换算成华氏度”。路由先安排检索成员读取场馆、日期及预报来源，取得摄氏度后再安排计算成员换算。复核要求地点、时间、原始数值、单位和来源互相一致。最后由用户选中的人设交付一个答案。简单问候应产生零个成员请求。没有计算工具、网络受限、权限拒绝、超时或用户停止时，回执要能核对相应成员是否真正运行。

## 2026-11-04 实施边界（基准 0771e46）

用户选定按需分工。普通回答的模型兼任路由，通过宿主控制调用分派有依赖的子任务；每项工作只使用当前对话连接、该岗位工具交集以及独立的请求上下文。金冬天和懂王的身份、可委派的外部 Agent 及账号配置不作迁移。原始目标与用户限制属于整轮，控制调用本身不能充当完成证据。

桌面 createInvokeModelNode、手机 AgentLoop.invokeModel、Android SharedChatAgent.execute 负责模型请求、工具实际分发、取消/预算及最终核验。共享核心在各自正常循环内决定岗位表、校验分配与制作有限交接；模型界面和执行器两处检查岗位工具。核对普通聊天、连续检索到计算、无证据、越权、拒绝/取消和手动团队入口，记录在现有执行场景。审计停在既有工具执行器与提供方适配器，无需改发布、账号、长期记忆或同步线协议。

## 已实施的按需分工

- 当前对话的模型在原有回复轮决定是否调用 route_task。可选岗位由宿主实际工具表与用户限制求交集。检索、资料读取、计算和执行各有工具白名单，受权执行仍走原审批，外部自定义 Agent 的委派设置独立生效。
- 成员只收到原始目标、分派的子任务、该岗位的工具和该成员的临时消息。交接使用提供方原有的工具调用与返回配对。宿主生成证据 ID，区分已观察、部分和未核验。主 Agent 在原对话继续分工或核验并回复。
- 每次请求最多 6 项分派，每位成员最多 6 轮工具。重复的相同任务、嵌套分派和跨岗位调用不会进入执行器。共享截止时间、调用次数、token 预算与用户停止始终约束整个对话。成员回执单独命名，原有成功写入及不确定结果有防重保护。
- 计算岗位在三端使用确定性的数值计算。表达式只解析数字、运算符和白名单数学函数，温度换算返回输入、单位、数值。执行场景使用“检索成员”“资料读取成员”“计算成员”“执行成员”的岗位名称。

## 运行证据

- 桌面生产图的脚本模型和 iPhone AgentLoop 夹具：检索 20°C → 计算成员越权读页被拒 → 计算 68°F → 当前对话 Agent 核验交付。iPhone 使用相同的原始调用 ID 验证成员间隔离。简单问候和子模型失败分别核对请求数与部分交付行为。
- Android 只读 QA 模拟器通过普通聊天入口运行岗位测试，已回收模拟器。断言检查计算成员的请求只有计算器，无法调用日历，主 Agent 恢复原人设并收到真实计算回执。记录见 .tmp/internal-routing-20261104/android-instrumentation.xml。
- 真实模型 gpt-6.1-sol，临时工作区的 forecast.txt 写入合成预报 26°C 和来源标记 R72。普通用户措辞未指定流程，模型自行读取文件，派给计算成员，交付 78.8°F、换算公式与来源，回执 completed。未调用个人日历。[可随仓库复查的脱敏回执](evidence/internal-routing-20261104.json)保存了模型实际返回、岗位、调用 ID 与结果。
- 最终组合回归 run-OeYShm 通过 4,842 项 JavaScript 测试、38 套 Swift、Android JVM / Lint / Debug / Release、设置页浏览器、生成器与资源校验，JavaScript 零失败、零跳过，未触发隔离复测。使用 393 × 852 英文浏览器实点计算成员详情，截图在 .tmp/internal-routing-20261104/handoff-en.png。最终 iOS 模拟器构建通过。续做沿用原始目标的限制，成员需要更强模型时把尚未执行的工作交回主 Agent。
