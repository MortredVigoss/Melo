# 对话 Agent 分工与任务空间记录

基准 889174f。桌面实际配置中，金冬天与懂王均关闭委派。模型档位只选择模型。桌面和 iPhone 已有显式团队、成员权限交集、交接与主 Agent 汇总。普通聊天是否采用自动分工是另一项产品决定。

## 已复现的记录断点

iPhone 的 deviceToolContext 收到 open_url 或 web_screenshot 的结果后调用 stage。ExecutionRecord.recordStage 默认写入模型模块 create。桌面与手机共用的 executionPanel 根据 operations 计算调用次数，根据 sources 显示来源。读取回调遗漏了这两项，后续供应商快照还会覆盖本机观察。

本次从工具执行后的结构化回执记录检索、手机工具和读取历史，区分实际执行与执行前拒绝，按 URL 身份合并来源。旧版回放只按已知的宿主事件 ID 分组。覆盖多页、失败、截图、重复观察及新旧记录混合，真实内容缺失时保留未知。验收包括 Swift 回执、共享界面回放和手机资源构建。范围限于任务空间，发布、安装和个人配置独立。

## 内部调度候选方案

- 按需分工（9/10）。简单对话由当前人设直接答，复合任务按依赖拆分为检索、计算、受权执行和复核。检索交接要有来源与读取状态，计算交接应有输入和结果。路由核对原始目标，按证据补缺或部分交付，由原人设回复。延迟和模型用量较低。
- 每轮启动独立路由模型（6/10）。问候与单步任务也经过路由。执行路径一致，每轮增加请求与延迟。
- 两种方案均应继承当前 Agent 权限与取消/预算，按实际成员标明执行身份，已生效的写入不得重试。外部自定义 Agent 的委派白名单仍是独立授权。产品方案等待用户选择。

## 执行器核对与推荐落点

| 层次 | 现有入口 | 需要补的行为 |
| --- | --- | --- |
| 对话入口 | 桌面 invokeModelNode，iPhone ChatStore.runTeam | 保留选中的金冬天或懂王作为对话身份、模型配置与回复者。普通请求还没有自动生成成员计划。 |
| 成员 | 桌面 runConfiguredMember、iPhone AgentTeam | 复用成员独立上下文、预算、停止和交接。内部岗位用稳定职责和工具白名单标识，禁止按显示名匹配。 |
| 主持与核验 | 桌面 runAgentTeam 和 teamCompletion，手机 runTeam | 校验原始目标的每一项。成员已查到演唱会城市，但天气仍为空时，交还检索成员继续查。到预算仍缺天气才给部分完成。 |
| 宿主差异 | Android SharedChatAgent 已按 search 操作写入网页检索 | 任务拆分协议可共享。每端先公布当前可执行的岗位；Android 原生对话未查到与桌面和 iPhone 等价的团队执行入口。 |

按需方案可用这条任务做验收：用户问“查演唱会当天气温，换算成华氏度”。路由先安排检索成员读取场馆、日期及预报来源，取得摄氏度后再安排计算成员换算。复核要求地点、时间、原始数值、单位和来源互相一致。最后由用户选中的人设交付一个答案。简单问候应产生零个成员请求。没有计算工具、网络受限、权限拒绝、超时或用户停止时，回执要能核对相应成员是否真正运行。

## 任务空间验证

- 旧 iPhone 回放用宿主自有的事件 ID 前缀配合固定操作名识别，桌面模型阶段以及执行前拒绝的事件维持各自分类。投影视图不改历史存档。只有页数摘要而无链接的记录继续显示零来源。
- 新回执把本机网页读取、截图、手机操作和历史读取写入 operations。页面打开、实际非空正文、部分正文和回答引用分别标记。重复回调和重复供应商观察不会增加计数；HTTP 错误没有读取成功的来源。协作成员的调用有各自的 ID 前缀。
- 393 × 852 的 Chrome 实际加载 iPhone 的离线资源并点击模块与详情。英文夹具显示 1 条模型阶段、2 次网页调用、0 条来源，失败详情正确，分页文字为 “Read page 1 of 2”。截图在 .tmp/agent-scene-20261104/。另已完成无签名 iOS 模拟器构建，本次没有真机安装。
- 最终回归 run-lQI4u4 通过全部 2,241 项入选 JS 测试、38 套 Swift、设置浏览器、Android JVM / Lint / Debug / Release。此前 run-LfZWSL 在 Swift 编译期间源文件仍在修改，被编译器中止；最终回归使用稳定源码从头完成。桌面本机未找到与截图日期及 BIGBANG 查询匹配的原始场景，页面复验使用同形状的历史夹具。
