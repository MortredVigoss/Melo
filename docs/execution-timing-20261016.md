# 执行计时与图片进度（2026-10-16）

用户要求显示已思考秒数、最终用时、图片百分比及生成完成时间。本轮按现有执行记录实现，不改模型、权限、循环上限或真实数据。

## 实施方案

1. 聊天回复旁与任务空间显示秒级计时：运行时持续更新；结束、失败、取消后冻结。总用时覆盖本轮等待、模型与工具；模型请求用时单独标为“思考与回复”，不推测模型内部推理耗时。
2. 使用已记录的开始/结束时间，历史回看与刷新保持一致；缺少时间的旧记录显示未记录，不能用当前时间补造。展示本机时区的完成日期时间。
3. 图片百分比按“已保存张数 / 请求张数”计算，明确标为成果进度。预览帧不算完成，失败/取消不补满 100%。云端未提供逐张生成百分比时明确说明；不按耗时模拟。显示图片处理用时及成果保存时间。
4. 桌面只每秒更新计时节点，不重建消息、图片或三维场景；隐藏页面暂停更新。iPhone 原生聊天同步计时与完成记录，任务空间使用同一渲染器；补齐界面语言。
5. 回归覆盖冻结、刷新、并行模型时间合并、缺失/无效时间、图片预览/部分失败，浏览器窄屏与原生 Swift 校验。保留其他线程 WIP，仅本地提交本轮片段，不运行 git pp、推送或安装。

- `desktop-ui/executionTiming.js`：基于执行记录计算总用时、模型请求区间并集、成果比例和保存时间；历史缺失/重建记录不补造零秒。`executionPanel.js` 在任务空间和消息回看按钮旁展示，秒表只更新运行中的计时节点，隐藏页面不更新；`app.js` 在服务静默时也更新等待提示。
- iOS `ExecutionRecord.swift` / `ChatStore.swift`：原有时间戳继续作为依据，图片成功保存和绑定后记录本机成果计数。`ExecutionWorkspace.swift` / `ContentView.swift`：原生聊天、三维任务空间、渲染失败回退都可查看计时。新增观察字段不进入原有冻结同步协议，旧记录可读。
- 五种界面语言已补齐；共用场景由 `build-scene.py` 生成，未手改压缩包。
