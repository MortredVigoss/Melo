# 第二轮运行链路审计与验收（2026-10-10）

本轮根据用户提供的 Claude 报告，先在当前共享工作树复现，再修确认项。方案范围是权限隔离、交付重试、上下文连续性及中断恢复；不迁移账户，不改模型供应商协议，不清理用户历史。其他线程的 WIP 保留。本记录以改前副本为基线，不把报告里的行号当成当前源码事实。

## 复核与处理

| 报告项 | 当前处理与边界 |
| --- | --- |
| 同工具并行授权覆盖 | 成立。界面按 requestId 保留每个请求，重复事件不产生重复弹窗。同一轮两次 PDF 调用分别可处理。 |
| skill 绕过 Agent 工具范围 | 成立。主循环向工具传递当前可见工具集合，skill 的空调用方白名单表示零工具；嵌套执行继续继承范围。被屏蔽的 MCP 不能靠 skill 重新获得权限。 |
| 失败丢语音转写 | 成立。发送失败恢复文字、附件、转写内容及对应音频 id，避免重发退化为重新识别。 |
| 断线重发重复执行 | 成立。未改动的失败草稿复用请求 id；内容、附件、图像任务、角色或会话模型选择变化后使用新 id。完成的请求回放现有回复。明确中断且结果不明的请求不会自动重跑，需用户核对后显式发起新请求。重试状态目前保存在当前窗口内存，关闭窗口后不保留。 |
| 超长首轮堵住压缩 | 成立。对无法装入单次压缩的最早完整轮次使用有上限的摘录，明确标记内容省略；成功后推进边界。原始消息不修改，未宣称完整压缩了被省略内容。 |
| 预算中间跳过历史 | 成立。最新必要消息仍按原规则保留；向前选历史时第一次放不下即停止，避免旧的短消息越过缺失的新轮次。 |
| 审批 running 永久卡住 | 成立。只在进程启动将遗留执行标为结果待核对，保留核对后关闭入口，不自动重新执行。所有未处理记录保留，24 条限制只作用于已结束历史。系统→工具与任务实际接入审批面板。 |
| 手机旧消息无 createdAt | 成立。排序及可携带导出使用稳定的有效日期兜底，重复合并不凭空产生当前时间；系统消息仍保留。外部传入的同步协议校验不放宽。 |
| subAgent 全局环境与 team 模型 | 成立。在本轮模型选择后绑定连接；skill、子任务和 team 继承同一请求环境和已解析模型，避免异步间读到别的请求的模型或凭据。 |
| 暂停/结果不明的提醒 | 该报告落后于当前代码：工具说明和列表已经标记状态。保留待核对记录及数量限制是有意行为；重启不能证明外部消息未送达，不会自动重复推送。可核对后取消、重新设置。 |
| 原生语音无时限 | 不完全成立：Swift 已有 60 秒录音上限和结束等待期限。本轮补网页与原生桥接丢失结束消息时的超时处理；保留已有文字并恢复可操作状态。 |

上一轮 `runtime-audit-fixes.md` 中“缺失日期已有标准化、旧语音字段没有有效写入源”的结论过于宽泛；本轮真实路径测试证明仍有缺口，以上修复覆盖这两项。运行中重复请求现在有独立状态说明，不再误称已中断。

## 证据与验收

- 失败复现及修复后专项回归：389 项通过；最终界面测试 345 项通过，语法检查与 diff 空白检查通过。修正 team 测试断言后该测试文件再次通过。
- 总门禁已完成：执行的检查通过；两项系统入口原生启动检查显式跳过，因此总状态为 YELLOW，不写成全量 GREEN。最后的审批入口及语音桥接补充改动另经完整 UI 测试验证。
- 实际浏览器：同一轮的两次 PDF 权限请求按顺序出现、分别拒绝，无读文件副作用；服务启动后中断审批显示待核对，关闭后不会执行旧命令。
- 实际浏览器断线验收：测试代理在服务端保存回复后丢弃完成通知，原样重发的两次请求 id 相同；仅一条用户消息、一条最终回复，模型夹具调用数从重发前到重发后均为 6，没有重复工具授权。模型是本地可控夹具，未调用真实供应商账号。
- 正式 Mac 安装包已构建更新，并通过直接启动其可执行文件重开；新前后端进程及系统页审批入口已观察到。原有 9 段对话 id/内容、6 个角色主要资料和模型配置核对一致，最终停在个人资料设置页。
- 系统应用服务方式重开仍曾停在启动页；直接执行安装包内程序可以进入界面。这是已有的独立启动问题，不能把本轮开发启动验收等同于 Dock/Launchpad 冷启动通过。
- 本轮没有覆盖安装 iPhone，也没有测试真实云模型、真实麦克风转写、Telegram 或 Discord 送达。
