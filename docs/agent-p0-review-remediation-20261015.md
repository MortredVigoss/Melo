## 1. 保存后旧频道/语音配置覆盖新值（P1 优先级）

原因：磁盘格式 3 拆分了频道和语音表，但 hydrateState 将这些旧表和运行时 Agent 兼容视图同时保留。事务写入新表后，缓存发布从旧 state 再次 hydration，旧表覆盖新视图，下一次无关保存又把旧值写回磁盘。

隔离临时 home 真实事务已复现：`diskInitiallyNew=true`、`runtimeWronglyOld=true`、`followingSaveRolledBack=true`。没有读取或输出用户凭据。证据：开发目录 `.tmp/agent-p0-review-proof.json`。

拟修复：
1. 明确边界：持久化分表是磁盘格式；加载后只保留一套可写运行时配置，消除旧分表与兼容视图同时充当可写来源的情况。
2. 写盘、发布常驻缓存、返回保存结果都来自同一份新提交快照。磁盘提交失败时不得发布新缓存；不能把省略消息正文的磁盘聊天清单误作运行时完整聊天。
3. 全局和项目级配置走同一转换链路，频道、语音、清空和项目覆盖重置均验证；旧数据备份和已有聊天检查点逻辑保留。

验收：用新进程冷加载格式 3 数据，修改令牌和音色，检查保存返回、bootstrap、运行时读取、磁盘一致；再保存无关字段并重启，仍为新值。重复覆盖全局/项目、清空、失败写盘、并发窄字段保存、跨 home，以及频道凭据不进入同步导出。

2. 浏览器端保留下载；两端导出同一份当前草稿，UTF-8 字节和换行一致。
3. 取消显示“已取消导出”，不显示成功；写盘失败保留编辑草稿并明确提示；成功以原生保存回执为准。
