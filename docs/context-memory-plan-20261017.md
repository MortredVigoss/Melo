# 同一对话里来回换话题、跨对话记忆与 token：现状与方案（2026-10-17，Claude）

用户问题：同一条对话里先问 A、再问 B、再问 C、又回到 A，现在怎么处理？不同对话之间（做项目 / 不做项目、不同 Agent）记忆是否共享、会不会串？哪些是全局、哪些只在一处？同时要考虑 token 消耗。先出方案，用户选择后再实施。

> **2026-10-17 晚更新**：本节「现状」有 5 处与代码不符（预算单位混用、6 条保底不绝对、超窗后仍有召回、缓存失效根因不止顺序、共享事实非每轮都带），逐项核对见 `docs/architecture-agent-context-audit-20261017.md` §3.2。同日已落地：云端模型默认总预算 160k（历史窗口 114k）、压缩触发与窗口同源不再有盲区、中文估算校准、逐轮内容移入当前用户消息（系统提示与历史可缓存）、项目说明不再被丢弃、摘要降级可见并自动重试、`search_history` 按受众与项目隔离。方案二的 1B / 2B 仍待用户选择。

## 一、现状（读代码与本机记录确认）

### 1. 同一对话内

| | 电脑 | 手机 |
| --- | --- | --- |
| 发给模型的历史 | 最近的原文消息，按 token 预算往前取，最多约 6 万 token；至少保留最后 6 条 | 最近的原文消息，最多 60 条、约 48 KB 文字（中文约 1.6 万字） |
| 更早的历史 | 总量超过约 8 万 token 时，用模型把旧部分压成一份 6 段式摘要（意图、事实与决定、已完成、未完成、风格、最近上下文），放进系统提示 | **没有摘要**，超出窗口的内容直接不发 |
| 对话内事实 | 每 4 轮用模型抽取一次“事实”（偏好、决定、纠正等），默认只用于本对话 | 每条用户消息按规则抽取（不调用模型），默认只用于本对话 |
| 话题意识 | 没有。A/B/C 混在一起按时间顺序发送 | 没有 |

结论：
- A→B→C→A 时，只要还在窗口内，电脑会把 B、C 的全部原文也一起再发一遍；能答对，但贵。
- 超出窗口后：电脑只剩摘要里关于 A 的几句；手机上 A 直接没了。
- 本机记录的 24 轮电脑回复：每轮输入中位数约 1.27 万 token，最大约 10.5 万 token；其中**只有约 4% 命中了提示缓存**。原因是每轮都会变的内容（召回的记忆、知识片段、工具说明、语言要求）放在系统提示里、排在历史前面，导致后面整段历史每轮都不能复用缓存。

### 2. 不同对话之间

| 内容 | 作用范围 | 会不会跨对话 |
| --- | --- | --- |
| 对话原文、压缩摘要 | 本对话 | 不会 |
| 自动抽取的事实 | 默认“本对话” | 不会；用户在记忆页手动改成“项目 / Agent / 个人”后才共享 |
| 个人范围的事实 | 全部本机对话 | 会（只有用户手动设成个人的才会） |
| Agent 范围的事实 | 同一 Agent 的所有对话 | 会（手动设定的） |
| Agent 人设（IDENTITY / SOUL 文档） | 该 Agent 的所有对话（项目可覆盖） | 会，这是设定不是记忆 |
| 项目说明、目标、项目知识资料 | 项目内所有对话、所有 Agent | 会 |
| 项目内的审批、任务记录 | 项目内所有对话 | 会 |
| 聊天记录搜索工具（模型按需调用） | **全部对话，不分项目** | 会，这是目前唯一的“串”口子：项目 A 的对话里，模型可以搜到项目 B 或私人对话的内容 |

结论：
- **做项目时**，不同对话、不同 Agent 共享的是“项目说明 + 项目资料 + 审批/任务”，**不共享讨论出来的结论**。在对话 1 里定下的做法，对话 2 默认不知道，除非用户去记忆页把那条事实改成“项目”。没有自动维护的项目记忆文档。
- **不做项目时**，对话之间基本隔离；例外是手动设成个人 / Agent 的事实，以及不分范围的聊天记录搜索。
- 手机的项目资料是整篇放进提示（最多约 1.2 万字），电脑是按问题挑相关片段。

## 二、方案

分两部分：线程内（问题 1）和跨线程（问题 2），外加一项两边都受益的 token 改造。每部分 A/B/C 三选一，可以组合。

### 问题 1：同一对话里来回换话题

**1A 现状加小修**
- 手机补上电脑已有的“超出窗口时自动摘要”，长对话不再丢掉早期内容。
- 其余不变。
- 优点：改动小。缺点：A→B→C→A 仍然每次把 B、C 原文再发一遍；摘要是一整块，回到 A 时细节可能已被压掉。

**1B 话题分段（推荐）**
- 每条消息自动归到一个“话题”。电脑借用每轮已有的快速意图判断顺带给出话题，不增加请求；手机用系统自带的本地语义模型判断，判断不了就算“延续当前话题”。
- 每个话题维护一张“话题卡”（几行摘要：在问什么、结论、未完成）。
- 每轮发送：最近 3 轮原文（不管是什么话题，保证“那个呢”这类接话不断）+ **当前话题的历史原文**（回到 A 时把 A 的原文拿回来，哪怕很久以前）+ 其他话题各一行的目录。
- B、C 和当前问题无关时只占一行，不再整段重发；话题内容超出预算时压成话题卡，而不是整段对话一起压。
- 对话里显示很淡的话题分隔标记，可以点回某个话题；不强迫拆对话，也可以一键“把这个话题拆成新对话”。
- 判断错了也不会丢：最近 3 轮始终原样发送，其他话题目录在提示里，模型能看到“之前聊过 A”。
- 预计长对话每轮输入可降到现在的一半左右（需实测）。

**1C 按需检索**
- 只发最近几轮 + 摘要，更早的内容按当前问题在本对话里检索相关片段再放进去。
- token 最省；但“刚才那个方案第二点”这类隐含指代容易检索不到，答非所问的风险最高。

### 问题 2：跨对话记忆

**2A 收紧现状**
- 聊天记录搜索按范围限制：项目对话只搜同项目；非项目对话只搜非项目对话；跨项目必须用户明确要求。
- 记忆页和回复旁加“记到项目 / 记成个人习惯”一键操作，取代现在要去记忆页改下拉框。
- 优点：堵住串的口子，改动小。缺点：项目里讨论出的结论仍要靠手动共享。

**2B 分层记忆：个人档案 + 项目记忆本（推荐）**
- **个人档案（全局）**：你的偏好、称呼、习惯，几百 token 以内，每个对话都带上；来源是个人范围的事实，可以查看和修改，两端同步。
- **项目记忆本（每个项目一份 Markdown）**：固定几节（目标、约定、已定的决定、当前进展、待办、关键文件），控制在约 2000 token 以内。项目里所有对话、所有 Agent 都读它。
  - 写入：电脑每 4 轮抽取事实时，识别“决定 / 约定 / 进度”并提出更新；对话压缩时也会更新。每条都带来源对话，可以点回去看。
  - 你可以直接编辑；自动更新不覆盖你手改的内容，有冲突时标出来请你确认。
- **对话自己**：原文、话题卡、本对话事实，只在本对话。
- **非项目对话**：只共享个人档案；对话之间不自动共享。需要时由模型按需搜索（受 2A 的范围限制）。
- 同时包含 2A 的全部内容。
- token：记忆本和个人档案很少变动，放在固定前缀里，能被缓存，实际花费很低。

**2C 全自动语义记忆**
- 所有对话的事实和片段都进同一个记忆库，每轮按相关度跨对话召回，再按范围加权。
- 最“聪明”，但最容易串（私人话题出现在项目对话里），每轮召回的内容在变，token 不好控制，也很难解释为什么记得某件事。不推荐作为默认。

### 横切：让提示缓存生效（无论选哪个都建议做）

- 调整发送顺序：固定内容（系统规则、Agent 人设、个人档案、项目记忆本、工具说明）放最前面且每轮不变 → 对话历史 → 每轮变化的内容（召回的记忆、知识片段、当前话题目录）放到最后一条用户消息里，不再插在历史前面。
- 预期：本机记录的缓存命中率现在约 4%，改后连续对话中大部分前缀和历史都能命中缓存。缓存部分计费更低、响应也更快（具体折扣取决于服务商）。
- 同时在任务空间显示每轮实际输入 token、缓存命中多少，改前改后可以直接对比。

## 三、评分（5 分最好）

| 方案 | 解决来回换话题 | 省 token | 不串记忆 | 工作量小 | 可解释 |
| --- | --- | --- | --- | --- | --- |
| 1A 现状加小修 | 2 | 2 | 5 | 5 | 4 |
| **1B 话题分段** | **5** | **4** | 5 | 3 | **5** |
| 1C 按需检索 | 3 | 5 | 5 | 3 | 2 |
| 2A 收紧现状 | 2 | 3 | **5** | 5 | 4 |
| **2B 个人档案 + 项目记忆本** | — | 4 | 4 | 3 | **5** |
| 2C 全自动语义记忆 | — | 2 | 2 | 2 | 2 |
| 缓存友好的发送顺序 | — | **5** | 5 | 4 | 4 |

推荐组合：**缓存友好的发送顺序 + 1B + 2B**，两端一起做。

## 四、推荐组合的实施顺序

| 顺序 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 缓存友好的发送顺序 + 每轮 token 与缓存命中显示；聊天记录搜索按范围限制 | 同一对话连续多轮的缓存命中率明显上升；跨项目搜索被拒的测试 |
| 2 | 话题分段：两端共用一份判断用例；话题卡；发送规则；话题分隔标记 | A→B→C→A 用例里第 4 轮带上 A 的原文、不带 B/C 原文；最近 3 轮始终在；每轮 token 对比 |
| 3 | 手机补自动摘要（按话题压缩） | 长对话超出窗口后仍能回答最早话题 |
| 4 | 个人档案 + 项目记忆本，两端同步，可查看 / 编辑 / 追溯来源 | 对话 1 定下的约定，对话 2（不同 Agent）能用上；手改内容不被自动覆盖 |

## 五、需要你选择的

1. 同一对话：1A / 1B / 1C？
2. 跨对话：2A / 2B / 2C？
3. 如果选 2B，项目记忆本放哪：
   - Melo 内部（两端同步，推荐）
   - 项目文件夹里的 `MELO.md`（可进 git，写代码的 Agent 和其他工具也能读）
   - 两者都要（以 Melo 内部为准，自动导出一份到项目文件夹）
4. 非项目对话之间：完全隔离（只共享个人档案），还是允许模型在需要时搜索其他非项目对话？

## 七、2026-10-21 收尾（Claude）

用户在本线程选了 1B + 2B（另两项按默认：记忆本放 Melo 内部；非项目对话可按需搜索其他非项目对话）。核对 master 发现另一线程已于 10-17 按 `docs/tool-conversation-memory-design-20261017.md` 落地了主体：逐轮内容移到当前用户消息后（前缀可缓存）、`search_history` 按受众与项目隔离、账本式话题卡 + `read_history` + 回到旧话题的原文摘录（1D，即本方案 1B 的模型侧）、项目记忆本 + 个人档案（2B）。本线程 10-17 的并行分支 `claude/context-20261017` 与之重复，不合并。
