# Melo 手机端对齐执行协议

用户于 2026-10-08 指定。每次说“对齐”，默认同时包含功能、接口、Bug 修复、UI、交互和特效。按下列顺序执行，不能只读线程总结或只搬样式就称为完成。

## 1. 读共用总览中的三线程交接与实际代码 diff

2026-10-15 用户更新接手要求：每轮先读 `MELO_OVERVIEW.md` 中三线程的登记和交接，并核对实际源码；记录缺失、过期或冲突时才定向补读近期相关轮次，不默认全文回读。若线程已续接，确认当前主线并保留旧引用：

| 线程 | ID | 核对范围 |
| --- | --- | --- |
| melo主线 | `01a13b2e-5446-7042-bb5e-773129746c7e`（旧 `01a10bf2-e092-7862-87fe-2f237a8fb6a0`） | 接口、模型、请求与数据逻辑、修复、测试 |
| 设计 Melo | `01a1161a-1919-79c1-9764-8709bb0e2e2d` | 功能定义、任务流程、权限、恢复、配置与验收 |
| melo ui | `01a10bf3-d7b9-7832-a351-8b0f78e9c552` | 页面结构、组件、布局、材质、状态和特效 |

1. 先读取仓库工作规则、`git status --short`、对齐清单与上次验收基线，确认共享目录里的其他修改。
2. 从总览中的三线程交接、变更记录、提交、文件路径定位实际源码；必要时定向补读线程。线程不是独立 Git 分支；禁止凭线程名称猜测 branch。讨论和“已完成”总结不算代码证据。
3. 检查 `git diff`、`git diff --cached` 和相应提交差异。对未跟踪文件也要读取与比较；共享工作区大量源码可能尚未提交，`git diff` 为空不代表没有修改。
4. 优先与上次对齐保存的源码快照比较，并核对生成资源的 manifest/hash。仅有 hash 只能发现变化，不能替代阅读修改后的逻辑和关联调用。没有旧快照时明确记录“基线缺失”，读取完整文件并建立本轮基线，不能声称 diff 为空。
5. 把每条变更映射到手机实现，记录文件、旧行为→新行为、调用入口、依赖、测试及功能/UI差距。保留其他线程的未提交修改，不 reset、覆盖或顺手提交。

## 2. 先写本轮计划

在改实现前更新 `docs/mobile-desktop-alignment.md` 的本轮条目或关联专项计划，包含：

| 顺序 | 桌面变更 / 用户要求 | 手机改动 | 依赖与平台差异 | 验收方式 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 1 | 具体行为与证据 | 源码及真实入口 | 已解决 / 待处理 | 可复现检查 | 待执行 |

按依赖顺序排：数据与协议 → 功能与接口 → 状态与恢复 → UI与特效 → 集成验收 → 构建。当前明确授权范围内直接推进；重大产品分歧或必需信息缺失才请求用户补充。

## 3. 按计划顺序执行

- 每项先理解旧行为，再改手机端；复用共享逻辑和渲染资源时保留语义，不复制一份长期分叉的实现。
- 功能入口必须接到真实执行路径，错误、取消、恢复和状态文案一起做。新增可共用能力反向记录到主线交接清单。
- UI 同步包含布局、状态、动作、材质和实际效果；按 iPhone 尺寸适配坐标与滚动区域，不能机械搬桌面坐标。透明栏保持透明，内容在自己的视口内裁剪。
- 做完一项记录结果再进入下一项；依赖失败则先修复，不能拿按钮、占位、编译通过代替功能完成。
- 原账号、密钥、聊天与配置保留；共享目录不代表已接通跨端数据同步。

## 4. 功能与 UI 一起验收

- 跑相关故障回归、`npm run build:ios-scene`、`npm run test:ios` 和 iOS 构建；不为手机改动无故重启桌面端。
- 检查小屏布局、透明层、滚动裁剪、返回路径、来源预览和任务空间；特效必须反映真实状态，不能伪造执行进度。
- 涉及网络、授权、后台或设备的功能，分别列出离线协议测试、模拟器和真机结果；未做真实账号/设备检查的明确标为待验收。
- 分别记录源码、测试、构建、签名、安装、启动和真实功能验收，不能互相替代。仍有缺项则逐项列明，不把部分完成报告为全部对齐。

## 5. 交付与下轮基线

保存本轮三线程定位记录、diff/文件快照、资源 manifest 和验证结果到本机 `.tmp/` 专项目录；快照只包含源码，不能包含密钥或用户聊天。文档给出可定位的路径。

更新对齐清单、`PROGRESS.md`，运行 `npm run progress:codex`。用户要求覆盖安装时，再核对设备、bundle/team、数据保留、安装和启动；测试期间不擅自重启正在使用的应用。下一次从本轮基线继续核对。
