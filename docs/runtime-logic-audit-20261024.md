## 1. P1 — iPhone 禁用生图时提前返回，留下不可取消的“正在发送”状态

- 位置：[ChatStore.swift](../ios/Melo/ChatStore.swift) 447–459、519–525、827–829。
- 触发：所选 API 图片模型在连接里声明 `imageGen: false`，Agent 本机生成图片权限开启，然后发送生图/改图请求。
- 流程：先保存用户消息、创建并保存 `running` 执行记录，写入 `activeImageActions`，把聊天加入 `sendingChats`，再检查模型能力。拒绝分支只调用 `fail()` 并 `return`。
- 后果：执行任务及其 `defer` 还没有创建；`isSending` 始终为 true，后续发送/重试/删除被挡住。停止按钮只遍历 `runs`，此时里面没有这轮任务，所以无法清理；重新启动应用才会重建这些内存状态并恢复记录。
- 修复方向：所有可预检的模型能力在写消息/创建执行记录/占用发送状态之前判断；运行状态建立后所有失败必须走统一结束与清理路径。
- 验收：真实 ChatStore 入口拒绝后 `isSending == false`、无悬挂运行记录/队列，原图与草稿保留，改为允许后同一聊天可再次发送；停止和冷启动也要检查。
- 证据层级：源码控制流确认，未声称真机通过。

## 2. P1 — 同地址的不同模型连接会串用能力声明

- 位置：[modelCapabilities.js](../shared/agent/modelCapabilities.js) 31–35；[imageSettings.js](../src/images/imageSettings.js) 43–49；[openai.js](../src/openai.js) 1312–1314。
- 触发：A 是聊天默认连接，B 是单独的视觉连接；A/B 的 URL、协议和模型 ID 相同，但保存为两个连接/账号，能力设置不同。
- 原因：`visionConnection` 合并 B 的配置时保留 A 的 `activeLlmProfileId`；`connectionForModel` 只比较 URL、认证模式和协议，不验证连接身份，因此重新取回 A 的声明。
- 复现：B 的 `vision:false` 被 A 的 `true` 覆盖，模拟模型传输请求计数为 **1**，未被拦截；反向设置也会错误拒绝本来允许的连接。这是模型兼容声明隔离问题，不等同于 Agent 工具权限失效。
- 修复方向：传递所选连接的明确 ID/快照，不用地址猜连接归属；视觉覆盖、智能路由、直接模型调用都使用同一已绑定快照。
- 验收：同 URL/同模型但不同连接、不同密钥、相反能力的双向组合；被禁止的一方模型请求计数必须为 0。

## 3. P1 — 视觉探测一次失败后，重测会被旧失败结果自行拦住

- 位置：[modelCapabilities.js](../shared/agent/modelCapabilities.js) 25–29；[llmConnections.js](../src/services/settings/llmConnections.js) 126–152；[openai.js](../src/openai.js) 1314。
- 触发：识图连接测试发生临时网络错误/超时/限流，随后恢复服务，再点识图测试。
- 原因：任何 `visionTest.ok:false` 都被解释为 `vision:false`；再次探测仍携带旧记录进入普通聊天的能力闸门，尚未请求服务就遭拒。
- 复现：首次模拟网络故障后，重测的传输计数 **0**，错误为 `MODEL_VISION_DISABLED`；原本支持图片的服务也无法通过普通重测恢复。
- 修复方向：区分“探测失败/未知”和“明确不支持”；探测不受自己上次失败回执阻挡，同时尊重用户显式关闭并给出清晰操作入口。
- 验收：先超时/401/429/识别错误，再成功的连续探测；瞬时故障不得固化为能力否定。

## 4. P2 — 部分语音入口选择 Edge，仍优先请求 MiniMax

- 位置：[tts.js](../src/tts.js) 259–284；[ttsRoutes.js](../src/http/ttsRoutes.js) 192–207，以及调用 `synthesizeSpeech` 的远程语音路径。
- 触发：已有 MiniMax Key/音色，用户把 `ttsProvider` 改为 `edge`，通过 `/api/tts/speak` 或直接复用该合成函数的入口朗读。
- 原因：MiniMax 分支先于 Edge 分支执行，仅排除 `custom`，没有尊重显式选择 `edge`。
- 复现：配置选择 Edge，模拟请求却指向 `api.minimaxi.chat`。可能造成音色/计费与用户选择不一致，也把文本交给了不同的服务；本次测试没有真实外网请求。
- 修复方向：显式服务优先；自动兼容/回退仅用于自动模式或用户明确允许的回退。不能用“存在旧密钥”决定当前服务。
- 验收：保留多家凭据时逐个选择 Edge/自定义/OpenAI/MiniMax；未选择服务请求计数为 0。问题早于上轮提交，上一轮未覆盖该组合。

## 5. P2 — 缓存命中绕过新搜索正文预算，证据条数也未同步裁剪

- 位置：[webSearchTool.js](../src/tools/builtins/webSearchTool.js) 2008–2037；陈旧缓存分支及 URL 内容缓存有相同约束遗漏。
- 触发：以前按较大预算缓存过页面，后来把 `maxResults` 降至 1、`contentMaxChars` 降至 1000，再搜同一问题。
- 复现：结果列表显示 1 条，但正文输出 **6173 字符**，`completionSources` 仍返回 **8 篇 × 6000 字符**；网络请求 0，明确走缓存。
- 后果：用户降低预算后，旧缓存仍增加工具上下文和核验负担；结果列表数量和实际携带的证据集合不一致。
- 修复方向：缓存保持可复用原文，但每次返回统一应用当前条数、正文预算和证据 URL 子集；新鲜/陈旧/URL 缓存与新抓取走同一出口。
- 验收：先大预算填缓存，再小预算命中，检查 output、results、completionSources、contentItems 的一致性；同时覆盖反向扩大预算。

## 6. P2 — 历史旧话题把无关新任务也锁定在强档

- 位置：[modelRouting.js](../shared/agent/modelRouting.js) 13–27；[prepareNode.js](../src/services/chat/execution/prepareNode.js) 95。
- 原因：风险判断拼接传入历史里的所有 user 消息，没有按当前任务/话题完成状态划界。桌面传入整个聊天消息历史。
- 复现：新聊天的 `hello` 走轻档；历史里出现过已结束的法律问题后，同一句 `hello` 被判定为高风险强档，并直接跳过轻档判断。其他使用共享规则的端也受其传入历史影响。
- 后果：旧风险一直留在输入历史时，后续无关小任务不能回到轻/标准档，增加延迟和费用；没有配置强档时还可能直接阻止新任务。
- 修复方向：风险在当前未完成目标及其补充消息内保持，只在明确新任务/新话题时重新判定；不能简单只看最后一句，以免短续问丢掉真实风险。
- 验收：同一高风险任务短续问仍强；任务完成后明确新话题的普通请求可降档；纯闲聊不继承历史危险词。
