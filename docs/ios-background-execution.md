# iPhone 后台回复 — 2026-10-08

需求：切换应用或锁屏后，已发起的对话/检索尽量继续，收到的完整回答能保存；系统终止时应保留提问和真实中断状态。

检查证据：本轮读取 melo主线、设计 Melo、melo ui 的近期修改；核对桌面发送/取消/落盘链路与手机 ChatStore、场景生命周期、请求和存储。共享场景 manifest 与现有源码相符，完整功能迁移仍以既有对齐清单的缺项为准。本轮不扩大为全部桌面能力迁移。

现状：请求已由应用级 ChatStore 持有，但没有后台执行申请；进入后台只做前台同步，三份数据文件采用锁屏不可访问的 complete 保护。不能从这些缺口断言之前那次无日志退出已经定位。

## 顺序计划

1. 固定三线程 diff→计划→顺序执行→功能/UI验收协议。
2. 为每次用户发送申请短时执行保护，并在 iOS 26+ 申请 continued processing。系统拒绝则保持短时保护，不能重复发送网络请求。完成、停止、过期均释放资源；过时回调不能取消新请求。
3. 对话/偏好/执行记录采用首次解锁后仍可写的系统文件保护，迁移既有文件属性；密钥保留钥匙串设备绑定。后台过期先记录 interrupted 再取消；不保存半段输出为完整答案，不盲目自动重发。
4. 聊天页显示真实后台能力与中断后“重新生成”入口；返回仍保留提问。系统的进度只报告实际阶段，不能计时伪造百分比。
5. 运行生命周期回归、完整 iOS 门禁和构建；真机后台/锁屏另行验证。此轮没有新的安装要求，不主动替换用户正在使用的版本。

## 平台边界

[Apple 长任务说明](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados)允许用户主动发起的任务在后台继续使用网络，但系统/用户仍可停止，强制划掉应用也会终止。旧系统或调度拒绝采用[短时执行保护](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time)，不承诺固定分钟数。后台无限运行需要独立服务端执行与结果回收，不能靠手机保活模拟。

证据目录：`.tmp/ios-background/`。实施和验收结果在完成后追加。

## 实施与验收

前述 1–4 步已接入真实 ChatStore 发送入口，版本 0.5.5 (10)。iOS 26+ 使用 continued processing；同一请求立即持有短时执行保护，长任务获准后释放短时保护。系统拒绝不会重发或排队复制请求。完成、停止、过期都会结束后台任务，过期先保存 interrupted，返回后显示重新生成入口；应用重启仍可读取这个状态。回复保存失败会回滚内存里的完整答案，防止界面假装已保存。

三份本机数据的既有文件和后续原子写入使用 `completeUntilFirstUserAuthentication`。ChatGPT 续期凭证使用设备绑定的 `AfterFirstUnlockThisDeviceOnly`，初始化时只迁移这一项属性，不导出或复制密钥；其他钥匙串项保持原策略，API Key 在前台发送时捕获。锁屏仍是系统加密存储，需首次解锁；本次真机锁屏行为待验收。

已通过：9 组 Swift、手机桥接及资源一致性门禁；生命周期回归覆盖过期/停止/重复回调/迟到回调/系统拒绝，确保旧任务不能取消新请求。真实 ChatStore 模拟器验收覆盖过期后持久化、重启恢复、不重复提问的重试、手动停止，以及修改文件保护时保留原字节。

本次模拟器只授予短时后台保护，continued processing 的真机调度尚待确认。独立模拟器在无调试器附着下切到系统“设置”，延迟 12 秒的 fixture 回复在后台完成；返回 Melo 前已读到两条消息和 completed 任务记录，返回后再次核对。该证据验证后台执行与持久化链路，不代表真实模型/搜索服务或真机长时间运行已验收。模拟器不提供文件保护属性，此项明确保留真机锁屏验证。测试脚本会在任务完成后切回 Melo 读取诊断结果，不让已释放后台时间的诊断计时器影响结论。

复现命令：先在专用模拟器安装 Debug 构建，再运行 `python3 ios/scripts/verify-background-simulator.py SIMULATOR_UUID`。只使用隔离 fixture，不访问真实模型。完整 diff、三线程定位、源码快照及 manifest 保存于 `.tmp/ios-background/`。

此轮未覆盖安装实体 iPhone。Release 编译与签名状态分别记录在 `ios/VERIFICATION.md`，不能把签名等待算成功。此前无日志的退出/秒开问题仍不声明修复。
