# iPhone 图片保存反馈与防重复

用户反馈：看不出图片是否已保存，连点三四次会保存多份；要求首次保存一次，后续提示已保存并询问是否再次保存。

## 方案与实现

采用所有入口共享的本机保存记录与并发锁（方案 9/10），而不是每个视图单独维护忙碌状态。按原有不可变图片 ID 记录成功：聊天缩略图、图库长按、预览长按和顶部按钮使用同一路径；处理后的新图有新 ID，独立保存。

1. 申请照片添加权限前即锁住该图片，保存过程中显示进度，重复调用不执行写入。
2. Photos 成功回调后才记录成功；显示绿色勾选、常驻“已保存到照片”提示、缩略图“已保存”标记，并触发成功触感。
3. 再次点击弹出“这张图片已经保存过”，含明确“取消”和“再保存一份”；取消不写入，确认才新增一份。
4. 成功记录保存在本机 UserDefaults，重新打开与重启保留。失败不标成功，可重试；再次保存失败仍保留上次成功记录。原图字节、现有分享/存文件功能及照片添加权限范围保留。

实际文件：`ios/Melo/ImagePhotoSave.swift`、`ImageViews.swift`、`ios/Tests/ImagePhotoSaveTests.swift` 与测试/工程接入。新增提示同步到现有五语词条及生成目录；沿用暗色界面与系统确认框。截图见 `.tmp/ios-photo-save-20261015/{saved.png,repeat-confirm.png}`。

## 验证

- `ImagePhotoSaveTests` 通过：挂起首次写入时四次并发调用仍只调用一次 writer；多次未确认重试零写入；明确确认写一份；重新建立 store 保留成功；首次失败、重复失败和取消不误标；新图片独立。已接入 `npm run test:ios`。
- 当前 iOS gate：4 项 JS/共享资源检查与 23 组 Swift 通过；语言定向测试通过；Debug 模拟器构建通过，无本轮新增编译警告。未执行完整发布 gate。
- 首轮 iOS gate 因新增词条改变共享 renderer 哈希而失败，重新生成 Scene 后通过，保留首轮日志。首轮编译有主 actor 默认参数警告，改为方法内部取 shared 实例后消除。
- 独立 `Melo-PhotoSave-QA-20261015` 模拟器原生点击保存，出现真实“添加照片”权限提示；允许后系统照片库从 6 张变 7 张。再次点只显示确认；取消仍 7 张；明确“再保存一份”后 8 张。长按已保存入口同样先确认，取消后仍为 8 张。
- 进程退出并重新启动后，聊天缩略图与预览仍显示已保存，并再次询问确认；本机记录仅一个图片 ID。照片数量来自该专用模拟器 Photos 数据库只读核对，未读取用户实体相册。
- 核心证据 `.tmp/ios-photo-save-20261015/{ui-verification.json,source-after.json,test-ios-final.log,language-tests.log,build-verified.log}`；before/after 源码快照用于区分共享 WIP。

## 边界与交接

- 本轮未改用户实体 iPhone 权限、未签名/覆盖安装、未调用真实模型；真机触感和实际相册交互仍待装机验收。
- 记录表示 Melo 曾成功保存，不额外申请读相册权限来扫描旧图；更新前的历史保存没有记录，用户后来在照片中手动删除也不会清掉这份历史，因此确认框提供再次保存。
- 系统分享面板由系统/目标 App 管理，本防重复覆盖 Melo 的“保存到照片”，不声称拦截第三方分享动作。
- 源码仍共享 WIP；桌面主线可对齐“成功反馈、请求进行中去重、重复导出明确确认”的交互原则，但文件保存面板的覆盖规则须按桌面路径处理，不能直接套用手机图片 ID。
